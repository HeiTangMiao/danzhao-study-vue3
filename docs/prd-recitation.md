## 0. 事实基线（本次实测，可复核）

复核命令（在仓库根执行）：

> ⚠️ **统计口径（务必先读）**：本篇 PRD 区分**句数**与**空位数**。`block.items.length` 是**句数**；
> 真正要学员填的格子数必须对每句 `text` 跑 `/\{\{([\s\S]*?)\}\}/g` 计匹配数。全库有 **17 篇存在「一句多空」**，
> 两个口径不通用。**凡面向学员的"N 空"一律取空位数**（见 §4.2、P0-1）。

```bash
node --input-type=module -e "
import { collectFiles, importFresh, relPathOf, CONTENT_DIR } from './scripts/lib/load-content.mjs'
const rows=[]
for (const f of collectFiles(CONTENT_DIR)) {
  const p = await importFresh(f); const page = p.default || p
  if (!page || !Array.isArray(page.blocks)) continue
  page.blocks.forEach((b) => {
    if (b.type!=='cloze') return
    const items = b.items||[]
    let blanks=0
    for (const it of items) blanks += (String(it.text||'').match(/\{\{[\s\S]*?\}\}/g)||[]).length
    rows.push({file:relPathOf(f),title:b.title||'',mode:b.mode||'reveal',sents:items.length,blanks})
  })
}
const rv = rows.filter(r=>/自测|冲关/.test(r.title)), ls = rows.filter(r=>!/自测|冲关/.test(r.title))
const S=a=>a.reduce((s,r)=>s+r.sents,0), B=a=>a.reduce((s,r)=>s+r.blanks,0)
console.log('全库', rows.length, '篇', S(rows), '句', B(rows), '空')
console.log('正课', ls.length, '篇', S(ls), '句', B(ls), '空')
"
```

### 0.1 两处实测澄清

**（1）第 7 篇「填空自测（点击空位揭晓）」不是默写素材，一期不入背诵队列。**

它是 `mode` 缺省的 reveal 形态（点击空位揭晓答案），学员无从"默写"；且它位于 `05-文学常识` 单元，不属于默写专项。**有效复习篇由 7 篇收敛为 6 篇**（5 × 综合自测 + 1 × 综合大冲关，全部 input 形态）。正课数仍为 67，与来件口径一致，不受影响。

由此，**入背诵总量 = 73 篇 / 170 句 / 193 空 = 67 正课 + 6 复习篇**。

该篇功能不受任何影响——学员仍可在原单元页正常点击揭晓使用。

**（2）「一句多空」普遍存在，所以统计必须区分句数与空位数。**

全库 **17 篇**存在一句包含多个挖空（正课 15 篇）。例：`01-先秦至魏晋名篇.js` 有篇 2 句但 **4 空**；关雎的 strict 句「求之不得，{{寤寐思服}}。悠哉悠哉，{{辗转反侧}}。」一句话里就是 **2 空**。

这带来一个直接的实现约束：**用 `items.length` 渲染"N 空"会说错话。** 具体到素材：苏轼·水调歌头是 **1 句 / 2 空**——若取句数，卡面会显示"1 空"，学员进页面却看到 2 个输入框；关雎是 **2 句 / 4 空**，会显示"2 空"而实际要填 4 格。（见 P0-1 字段设计与 §4.2）

> 更正记录（v1.1）：本 PRD v1.0 曾把正课均值写作「1.79 空/篇」并据以判断"来件估错、单日负担更轻"。**该判断错误**——1.79 是**句数**均值，空位数均值是 **2.10**，内容侧「平均 2–3 条」的说法成立。此处已撤回，相关论据见 §6.2(3) 的改写。

## 1. 产品目标

> **让冲刺期学员每天花 1 分钟默写一篇古诗文，并按遗忘曲线自动重默，把"背过就忘"变成"到考场那天还记得"。**

三个正交子目标：

1. **给一个不用选的每日任务** —— 学员打开就有确定的一篇，不需要组卷、不需要挑单元，决策成本为零。
2. **让重复自动发生** —— 篇目按艾宾浩斯节奏自动回到面前，学员不靠自律记住"该复习哪篇了"。
3. **错字必须被抓出来** —— 默写的考点就是字，判分与课堂默写同一把尺，写错就是错。

---

## 2. 用户故事（冲刺期学员视角）

1. As a 冲刺期学员, I want 每天打开 App 就看到"今天该默哪一篇", so that 我不用花时间决定学什么，也不用在 67 篇里挑花了眼。
2. As a 冲刺期学员, I want 默写完立刻知道哪一句写错了哪个字, so that 我能当场订正，而不是带着错字进考场。
3. As a 考前一个月才想起背默写的学员, I want 系统把我背过的篇在第 1、2、4、7、15 天自动推回来重默, so that 我不会"每天学新的、前面的全忘"。
4. As a 昨天默写错了一句的学员, I want 这篇明天就再出现一次, so that 我能在忘记之前补上，而不是等它排到 67 天后再见。
5. As a 通假字总写错的学员, I want "辗转反侧"写成"辗转返侧"时被判错并提示课本原文, so that 我记住的是考场能得分的那个字。
6. As a 断更了三天的学员, I want 回来时接着上次的进度走，而不是被 3 篇欠账压垮, so that 我不会因为一次没做就放弃这个功能。
7. As a 单元学完的学员, I want 系统自动把这个单元的综合自测推给我, so that 我知道这一单元到底记住了没有。
8. As a 临考的学员, I want 随时能手动做一次「综合大冲关」12 句混合默写, so that 我能模拟考场压力、检验整轮效果。

## 4. 交互要点

### 4.1 入口与 Tab 融合

**不新增第 5 Tab**（`prd-mobile.md` 决策四已定档 4 Tab：学习 / 练习 / 复习 / 我的）。

| 位置 | 形态 | 承担的语义 |
| --- | --- | --- |
| **学习 Tab 首屏**（主入口） | 任务卡「今日背诵」：篇名 + 出处 + **`blankCount` 空** + 状态角标（新篇 / 第 2 次复习 / 逾期 X 天） | "今天该做的事"——与「继续学习」「今日待复习」同一层，是日课的心智 |
| **复习 Tab**（次入口） | 卡片「今日背诵 · 重默 N 篇」（N=0 时不占位） | "今天欠的重复"——复习 Tab 是今日待办的聚合地，缺了会漏做 |

两个入口指向**同一个队列与同一张表**，不是两套调度。

**首屏放得下第三张卡，不做合并（已定档）。** 「继续学习」「今日待复习」「今日背诵」是三个**不同队列、不同动作、不同表**的卡片；合并成一张"今日任务"多行卡，会让 P0-6「两个入口计数一致」的验收退化成三层嵌套，得不偿失。空间做法：复用现有 `continue-card` 的行高与内边距，**无任务时整张卡不渲染**（而不是留空壳）。

**为什么不放练习 Tab**：练习 Tab 的心智是"我要选一组题来做"（选学科→选单元→选题量→开始），有明确的选择与组卷；每日背诵是"不用选、给我一篇"，两者任务结构相反。把固定一份的日课塞进给学员自由组卷的 Tab 里，两边都别扭。

**为什么不放"我的"**：日课是每日行动项，不是低频查看数据。

### 4.3 单篇作答流程

**直接复用 `ClozeBlock` 的 input 形态，一个像素都不重画。**

```
点「开始默写」
  → 进入 /recite/:pieceKey，渲染该 cloze 区块（ClozeBlock，input 模式）
  → 学员逐空输入 → 提交
  → 逐空标红/标绿（ClozeBlock 既有行为，含 strict 红线）
  → 底部动作条：
       全对 → [ 记住了，明天见 ]  → 写 recite_progress: stage+1，排下次日期
       有错 → [ 再看错的那句 ] / [ 全部重默 ]
  → 学完点「完成今日背诵」→ 回首页，进度 +1，streak +1
```

关键取舍：

- **不给四档自评按钮**。默写的对错由机器判，学员不需要也不应该给自己打分。这是本功能与复习 Tab 最本质的差别（见 5.2）。
- **答错不阻断**。允许带着错字结束（ClozeBlock 已把错句入错题本），但不推进 `stage`，次日必现。比"必须全对才能过"宽容，比"写了就算过"严格。
- **离开保护**：沿用 `ExamBlock` 既有三层思路（父级状态注入 / `beforeunload` / 路由守卫）。

## 5. 与既有机制的关系（复用 vs 独立）

**这是成本的决定项，以下是明确判断，不是选项罗列。**

### 5.1 判定表

| 机制 | 结论 | 理由 |
| --- | --- | --- |
| **判分**（`answerMatches` + `CLOZE_VARIANTS` + 句级 `strict`） | **复用，零改动** | 内容侧红线 3。一期连组件一起复用 `ClozeBlock`，等于连"复用"都不用实现——根本没写第二份 |
| **作答形态**（挖空输入框 / 提交 / 逐句冻结 / 只重默错句） | **复用 `ClozeBlock` 组件** | 已在用、已过移动端适配（16px 防缩放、44px 触控、`data-no-swipe`、sticky 动作条）。重写一份是纯浪费 |
| **错句入错题本**（`recordError`，`source:'cloze'`） | **复用，且不改** | 已有闭环，句级补漏有独立价值；改动它反而会削弱错题本 |
| **存储 / 同步底座**（`studyDb`、IndexedDB） | **复用同一库** | 不新建存储引擎 |
| **复习 Tab 的 SM-2 四档自评** | **不复用** | 见 5.2 |
| **复习 Tab 的到期队列**（`pickDue`） | **不复用** | 见 5.3 |
| **背诵的篇级调度与进度** | **独立一张轻量表 `recite_progress`** | 见 5.3 |
| **练习 Tab 的组卷/自评链路** | **不复用** | 背诵不需要组卷，也不需要自评 |

### 5.2 为什么不复用复习 Tab 的四档自评

**语义冲突，不是成本问题。**

复习 Tab 的形态是「翻面看答案 → 忘了 / 困难 / 良好 / 简单」四档自评，且文件头写明了纪律：**不引入任何自动判分**（`ReviewView.vue:8`）。这套设计对 79.5% 无标准答案的数学自由文本题是**正确的**——判不了只能让学员自评。

但默写恰好是**能判的**，而且**判的是字**。让学员在复习 Tab 里看着正确答案点「良好」，等于把"默写"降级成"认读"：眼睛认识 ≠ 手能写对。考场上失分的正是那些"我看到就知道，一写就错"的字。

所以：**背诵的复习必须重新默写 + 机器判分**，这与复习 Tab 的自评范式不兼容。强行塞进去只有两条路，都不好：

- 放弃机器判分 → 默写的价值消失（这是内容侧红线 3 的精神，不只是字面）；
- 改造复习 Tab 支持"输入作答 + 自动判分"双形态 → 成本比新建一个背诵页更高，且会把"复习"这个清晰心智搅浑。

### 5.3 为什么背诵的调度要独立一张表（而不是复用错题本 / SM-2 队列）

三条理由，按重要性排序：

**（1）错题本装不下"答对的篇"。**
复习队列的入口是 `recordError`——只有**答错**才产生一行。而背诵的核心诉求是"答对的篇也要在第 1、2、4、7、15 天回来"。错题本在数据结构上就没有全对篇的位置。若走错题本，一期就退化成"只有答错的篇会重现"，正是内容侧反对的"只推新内容"的变体。

**（2）粒度不匹配：错题本是句级，背诵是篇级。**
`ClozeBlock.enqueueWrongSentences` 按**句**入库（`question` = 原句）。一篇 8 空的综合自测答错 3 句 = 3 张卡片。学员在复习 Tab 看到的是三句孤立的话，而他要练的是"整篇从头默到尾"。用句粒度承载篇级调度，会把一篇拆成一堆碎片。

**（3）独立一套的成本其实更低。**
表面上"新建一张表"听起来比"复用"贵，但算一下：

| 方案 | 实际工作量 |
| --- | --- |
| 复用错题本 + SM-2 | 改 `ClozeBlock` 入队逻辑（篇级聚合）→ 改 `pickDue` 支持篇粒度 → 改复习 Tab 支持输入作答 + 自动判分 → 改 `GradeButtons` 语义 → 双形态队列混排 → 回归复习 Tab 全部既有验收 |
| 独立一套 | 1 张表（5 个字段）+ 1 个 store + 1 个 view（挂现成 `ClozeBlock`）+ 1 个构建脚本 |

**结论：判分、作答 UI、入错题本、存储底座全部复用；只有"篇级调度与进度"独立。独立的部分是新增，不是改造——新增永远比改造一个已定型的模块便宜。**

### 5.4 与错题本的重叠如何处理（明确接受项）

背诵篇答错时，`ClozeBlock` 照常把错的**句**写入错题本（带「默写」角标），同时 `recite_progress` 把**篇**排到明天。于是同一处错误会两个地方都出现：

- 复习 Tab：一张句级「默写」错题卡（翻面自评，句级补漏）
- 每日背诵：整篇明天重默（机器判分，篇级巩固）

**一期明确接受这个重叠，不做去重（已定档，架构师确认无隐藏成本）。** 理由：二者粒度与动作不同（一句 vs 一篇、认读 vs 默写），去重反而会砍掉其中一个价值；且 `enqueueWrongSentences` 一行不改，不触碰已验收的链路。

**唯一可观测后果（QA 需知悉，勿当缺陷报）**：`recordAnswered` 记的是 `blanks.length`（空位数），所以「今日答题数」会包含默写填过的格子数。这属于**正确语义**——学员确实填了那么多格——不是数据污染。二期（P1-4）看真实数据再决定是否去重。

## 6. 内容侧三问 · 回函正文

### 6.1 问题一：是否认可「一期只做语文默写、复用 cloze、不新增类型」？

**完全认可，且我方实测后认为这个方向比来件描述的还要省。**

来件担心的是"新增类型的七处成本"，而实际连"复用"这一步都几乎不用写——`ClozeBlock` 已是完整的 input 作答组件：挖空输入框、提交逐空判定、逐句冻结、全部重默、只重默错句、错句自动入错题本，且已过移动端适配与判分验证。**一期只需新建一个页面把它挂上去，再配一张调度表。** 判分一行都不用写。

同时我方确认**接受全部四条红线**（第 7 节）。

一处需要内容侧知悉的收敛：来件列的 7 篇复习篇中，第 1 篇「填空自测（点击空位揭晓）」是 `mode` 缺省的 reveal 形态、且位于 `05-文学常识` 单元，**不是默写素材**，我方一期不纳入背诵队列。**有效复习篇 = 6 篇，正课仍为 67 篇**（与来件口径一致）。该篇在原单元页的使用不受任何影响。

由此入背诵总量为 **73 篇 / 170 句 / 193 空**（= 67 正课 + 6 复习篇）。

另需说明一处口径：来件"平均 2–3 条"的估算，按**空位数**实测为 **2.10 空/篇**（141 空 / 67 篇），落在区间内，**我方按此设计、不作调整**。此前我方内部曾按"句数 1.79"误读过一次，已在 v1.1 更正——`items.length` 是句数，全库有 17 篇「一句多空」，两者不可混用。

### 6.2 问题二：间隔重复成本如何？能否一期先做「答错重排」最小版本？

**我方建议一期就做完整的艾宾浩斯节奏（第 1、2、4、7、15 天），不做降级。理由是：降级的成本省不了多少，但会把功能的意义降没。**

**（1）成本判断：真正的成本不在算法，在"给不给学员自评 UI"。**

艾宾浩斯固定档（5 个档位、间隔 [1,1,2,3,8]）**比 SM-2 更简单**——没有 `easeFactor`、没有难度因子递推、没有 `repetitions` 语义。真正的成本大头是 SM-2 那套**四档评分交互**（`GRADES` / `GradeButtons` / 学员每次要自己判断"我是良好还是简单"）。

而背诵**恰好不需要自评**：默写能机器判分，判分结果直接驱动调度就行。

> **全对 → 进下一档；有任一空错 → 档位归零，明天重现。**

去掉四档评分 UI 之后，艾宾浩斯固定档的实现量与"只做答错重排"**是同一量级**——都是一张表加一个日期计算，差别只在多几行"档位 +1"的逻辑。**所以"降级省成本"这个前提不成立。**

**（1b）退一步说，就算不考虑 UI 成本，SM-2 用在"纯机器判分"场景也是坏掉的——它比固定档更差。**

即使不考虑 UI 成本，把 SM-2 硬套到"只有 GOOD / AGAIN 两种结果"的场景，数学上就已经坏了：

- `easeFactor` 增量 = `0.1 - (5-grade)*(0.08 + (5-grade)*0.02)`。代入 **GOOD(4)**：`0.1 - 1*(0.08+0.02) = 0` —— **增量恰为 0，`easeFactor` 永不上升**。
- 代入 **AGAIN(0)**：`0.1 - 5*(0.08+5*0.02) = -0.8` —— 每次直降 0.8，很快触底 1.3。
- 结果：`easeFactor` 变成**只降不升的死字段**，对调度零贡献，还白占一个字段和一次迁移。

> **SM-2 的价值来自四档自评提供的信息量；没有自评，它就退化成"间隔 1 → 6 → 15.6 → 39…"的固定序列，而且这个序列还不是内容侧要的 [1,2,4,7,15]。**

另外两点顺带说明：要让它输出 [1,2,4,7,15] 必须改 `calculateSM2`，而该函数**同时服务着 `error_book` 的既有验收**（`prd-mobile.md` §5.4 的 SM-2 数据流）；改它就是拿已验收的链路去换一个更差的方案。

**（2）产品判断：只做答错重排 = 功能失去意义，我方不能接受这个降级。**

来件说得对——"只推新内容等于每天学新的、前面的全忘"。但"答错重排"是同一个问题的**另一种形式**：只有写错的篇会重现，**写对的篇永远不再出现**。而默写的遗忘恰恰发生在"当时写对了"的那些篇上。学员一路全对地走完 67 篇，一个月后一篇都想不起来，这个功能就白做了。

**（3）"一天 1 篇"的负担是合适的，但重复必须由调度来保证，不能靠学员自觉。**

实测 67 篇正课共 **141 空、均值 2.10 空/篇**（空位分布 1空×27、2空×27、3空×4、4空×4、5空×1、6空×2、7空×1、8空×1），与来件"平均 2–3 条"的估算**吻合**，单日负担设计成立，维持一天 1 篇不调。

也正因为单篇负担轻（多数篇半分钟内写完），**"重复"这件事就更不能缺**：一天只写两三个字、写完就再不见面，67 天下来的真实留存接近于零。所以在 P0-5 加了一条配套设计：**重默优先于新篇；当日到期重默 ≥3 篇时不再推新篇。** 这直接兑现"背诵的价值全在重复"——用重复把轻负担的日子填满，而不是靠加量。

**结论：一期实现内容侧建议的 [1, 2, 4, 7, 15] 节奏，用机器判分替代自评四档，成本低于现有 SM-2 复习。**

### 6.3 问题三：复习篇（7 篇）按单元节点推，我方是否有更好的处理？

**原则认可，但把触发条件从「单元节点」改为「文件节点」，并给「综合大冲关」一个常驻手动入口。**

**（1）把"单元"换成"文件"。**

来件建议"单元结束时推一次"，但实测发现**单元边界与素材边界并不重合**：

- 5 篇综合自测分别挂在 `01`~`05` 五个默写专项文件的末尾，与文件一一对应；
- 「综合大冲关」在 `06-高频易错字与冲刺.js` 里，而该文件**前 3 篇是正课**（通假字专项 / 形近易混字专项 / 高频错字专项）——它不是"整单元复习篇"，是"整轮复习篇"；
- 「填空自测」在 `05-文学常识` 单元，与默写专项**跨单元**（该篇我方已排除，见 6.1）。

按"单元"触发需要引入单元进度概念，而素材实际是按文件组织的。**改为按文件触发**：

> 某文件（`fileKey`）的所有正课篇完成首学后，次日推该文件的综合自测。

运行时只需按 `fileKey` 分组判断，零硬编码、零单元概念，且与内容文件的物理组织天然一致。5 篇综合自测由此自动落在各自文件的正课之后——正是来件要的"单元结束推一次"。

**（2）「综合大冲关」按整轮触发 + 常驻手动入口。**

- **自动**：67 篇正课全部完成首学后进入队列（对应来件的"整轮结束"）。由于 `06` 的 3 篇正课排在最末，这个时机天然正确。
- **手动**：背诵页底部常驻「综合大冲关（12 空 · 模拟考场）」，**随时可点、不限次、不计入调度**。

给手动入口的理由：来件说它"适合整轮结束或考前模拟"，但一个只能做一次的模拟卷，价值远低于一个随时能自测的模拟卷。它是全套素材里唯一"12 句混合、最接近考场"的篇目，锁在流程末尾太浪费。零额外成本，故放 P0。

**（3）复习篇也走同一套 [1,2,4,7,15]。**

它们同样是默写素材，同样需要重复，"推一次就结束"会浪费掉。统一走一套调度器，实现也更简单。

| A1 | 学员每日可收到 1 篇默写 | 新装首日进入 `/recite` 给出第 1 篇；完成一篇后指针 +1 |
| A2 | 复习篇不被当作每日新篇重复推送 | 首日不给任何复习篇；某文件正课走完前，其综合自测不出现 |
| A3 | 判分与现有 cloze **完全一致**（含通假红线） | **73 篇全量 parity 测试，不抽样**：对产物内每一篇，在背诵页与原单元页各跑一遍相同输入（含每篇全部空位的正解 + 一个故意错字），**逐空判定结果必须 100% 相同**。⚠️ 不得写成"随机抽 10 篇含 strict"——全库 strict 句**只有 1 句**（关雎「辗转反侧」），抽样命中的概率约 10%，等于没验。该 1 句必须**在用例清单里显式点名**：输入「辗转返侧」须判错 |
| A4 | 有间隔重复，非仅答错重排 | 全对一篇 → `nextDate` 依次为 +1/+1/+2/+3/+8 天（累计 1/2/4/7/15）；答错 → 明日重现 |
| A5 | 重默优先 | 构造 4 篇到期 → 当日无新篇；构造 8 篇到期 → 当日 5 篇 |
| A6 | 断更不产生欠账 | 断更 3 天后进入，仍只给 1 篇新篇 + 到期重默，指针不跳 |
| A7 | 进度真实、无假数据 | 「已背 X / 67」与 `recite_progress` 实际行数一致；无数据时不显示占位卡 |
| A8 | 综合大冲关随时可做 | 未整轮完成也能点击；完成后该篇调度状态不变 |
| A9 | 离线全程可用 | IndexedDB，不发起网络请求 |
| A10 | 移动端触控 | 卡片与主按钮触控区 ≥44×44px；输入框 16px 不触发缩放 |
| A11 | **卡面空数与实际输入框数一致** | 卡面显示「N 空」时，进入后输入框数量必为 N。**必须用「一句多空」的篇做用例**：苏轼·水调歌头（1 句 / 2 空）、关雎（2 句 / 4 空）。若显示"1 空"而输入框有 2 个，即为取 `items.length` 的缺陷 |
| A12 | `submitted` 事件回传准确 | 触发提交后，`{total, correct, allCorrect}` 与页面内逐空标色自洽；`allCorrect` 与 `correct === total` 恒等 |

### 9.1 已定档（本轮回填，不再是待确认）

| # | 议题 | 结论 |
| --- | --- | --- |
| 1 | **考试日期是否可得？** | **一期不依赖考试日期**。P0 全部按文件顺序推进；P1-1「高频优先排序」降级为学员手动开关，不做日期推算 |
| 2 | **`recite_progress` 是否纳入多设备同步？** | **一期不同步。** 理由：整行 LWW 会在两台设备同时推进时**静默丢弃**另一台的进度（整行覆盖），要正确同步必须做字段级合并 = 改同步引擎，二期再做。**但换账号清理 + 导出备份纳入一期必做**——进度是用户资产且属个人信息，不清理/不可导出是隐私缺陷 |
| 3 | **§5.4 的句/篇重叠是否接受？** | **接受，确认无隐藏成本。** `enqueueWrongSentences` 一行不改。唯一可观测后果：`recordAnswered` 记的是空位数，故「今日答题数」包含默写填过的格子——属正确语义，**QA 需知悉，勿当缺陷报** |
| 4 | **学习 Tab 首屏放得下第三张卡吗？** | **放得下，不合并。** 三者是不同队列/不同动作/不同表；合并会让 P0-6「两入口计数一致」退化成三层嵌套。空间做法：复用 `continue-card` 的行高与内边距 + **无任务时整卡不渲染** |
| 5 | **正课 40% 只有 1 空，是否提到 2 篇/天？** | **维持 1 篇/天，不提。** 实测均值 2.10 空/篇、单篇半分钟内写完，是"能坚持 67 天"的前提；轻的部分由重默补齐（P0-5），不靠加量 |
| 6 | 「整轮完成」之后做什么？ | 一期：进入"整轮完成"态，只推到期重默 + 常驻大冲关；P1-3 补里程碑页与"重开一轮" |

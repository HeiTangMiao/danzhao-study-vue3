### 1. 五分钟上手

#### 你要改的东西长什么样

每个学习页，都是一个普通文本文件，扩展名是 `.js`。它长得像这样（下面是数学「不等式的基本性质」这一页的真实开头，为了好读略去了一部分）：

```js
export default {
  blocks: [
    {
      type: "knowledge",
      title: "一、实数大小的比较",
      paragraphs: ["实数的大小关系通过它们的差来判定，这是不等式的理论基础。"]
    },

    {
      type: "formula",
      title: "作差比较法",
      formulas: ["a - b > 0 \\iff a > b", "a - b = 0 \\iff a = b", "a - b < 0 \\iff a < b"]
    },

    {
      type: "tip",
      text: "作差比较法的步骤：作差 \\(\\rightarrow\\) 变形（因式分解、配方等）\\(\\rightarrow\\) 判断符号 \\(\\rightarrow\\) 得出结论。"
    },
    // ……（此处省略本页后面的表格、例题、练习题等）
  ]
}
```

- **文件在哪**：`src/content/math/02-不等式/01-不等式的基本性质.js`（数学、语文、计算机分别在 `src/content/math/`、`src/content/chinese/`、`src/content/computer/` 下）。
- **哪几行是你能改的**：**所有引号 `"..."` 里面的文字**——标题、段落、公式、提示语，都是你的地盘。引号外面的东西（`type:`、`paragraphs:`、大括号、方括号、逗号）是「格式框架」，**不要动**，动了页面就会坏。
- **改完怎么让开发侧检查**：在项目里运行一条命令：

  ```
  npm run validate:content
  ```

  它会通读全部 139 个页面文件，把「格式坏了 / 公式写错了 / 标题漏了」之类的问题一条条列出来。看到 **✅ 全部通过！** 就说明你的改动是安全的；看到 **❌** 就把每条错误按它给的定位改掉再跑一次。

> 小提示：`type: "knowledge"` 这类字段叫「这个板块是什么」，决定了它在页面上显示成一段讲解、还是一个公式框。**换板块种类就等于换显示样式**，但标题和正文照旧填在引号里。

### 2. 内容怎么组织

#### 三层结构：学科 → 单元 → 页面

```
学科（数学）
└── 单元（02-不等式）
    ├── 01-不等式的基本性质.js      ← 一页 = 一个文件
    ├── 02-一元二次不等式.js
    ├── 03-绝对值不等式与分式不等式.js
    ├── 04-基本不等式与最值.js
    ├── 05-复习测验.js
    └── 06-易错专项与冲刺.js
```

三个学科各自的位置：

| 学科 | 目录 | 站点配置（登记页面清单） | 页面数 |
|---|---|---|---|
| 数学 | `src/content/math/` | `src/content/site.js` | 80 |
| 语文 | `src/content/chinese/` | `src/content/chinese/site.js` | 33 |
| 计算机 | `src/content/computer/` | `src/content/computer/site.js` | 26 |

#### 命名规则

- **单元文件夹**：`编号-单元名`，例如 `02-不等式`、`01-语言文字运用`。
- **页面文件**：`编号-页面名.js`，例如 `01-不等式的基本性质.js`、`07-复习测验.js`。编号一律两位（`01`、`02`……），保证排序整齐。
- 页面文件名**不带学科前缀、不带扩展名之外的修饰**。

#### 页面是怎么被「登记」的

单元文件夹里放的文件，本身不会自动出现在网页上，还必须在 `site.js` 的清单里**登记**一次。以数学「不等式」单元为例（真实内容）：

```js
{
  num: "02", title: "不等式", folder: "02-不等式", phase: 1, color: "#0d9488", icon: "⚖️",
  files: [
    { name: "01-不等式的基本性质", title: "不等式的基本性质", subtitle: "实数大小比较与不等式基本性质" },
    { name: "02-一元二次不等式", title: "一元二次不等式", subtitle: "三个二次关系与含参数讨论" },
    // ……（此处省略 03、04 两条）
    { name: "05-复习测验", title: "不等式 · 复习测验", subtitle: "本单元知识综合检测", isTest: true },
    { name: "06-易错专项与冲刺", title: "不等式 · 易错专项与冲刺", subtitle: "高频易错点 + 冲刺拔高题" }
  ]
}
```

要点：

- `name` 必须**与文件名一字不差**（不含 `.js`）；
- `title` / `subtitle` 是页面顶部和侧边栏显示的标题与副标题——**改标题就改这里**，不要在页面文件里另写一份（页面文件的「名字」只认 site.js）；
- `isTest: true` 表示这是一页测验，页面会走测验的展示方式；
- 单元里的 `folder` 必须与文件夹名一致。

#### 为什么页面顺序不能乱动

`files` 数组的**先后顺序就是页面的身份编号**（代码里叫 `fileIndex`，从 0 开始数）。网页的地址是按这个顺序生成的：

```
/study/math/02/4   →  数学 · 第 02 单元 · 第 5 个页面（下标 4）
```

也就是说：

- **往中间插入一页，后面所有页面的地址都会平移一格**，学生已收藏的链接、分享出去的地址就会指向另一页；
- **调换两页顺序，等于把两页对调了身份**，学习进度、错题本里「这一页做过没有」的记录会张冠李戴；
- 因此：**不要随意插入或重排**。确实要新增页面时，**加在单元清单的最末尾**（编号顺延，如 `07-…`、`08-…`），并同步在 `site.js` 的 `files` 末尾追加一条 —— 这一步请和开发侧一起做，避免只改一半。

> 记住一句话：**顺序即身份**。改动顺序 = 改动地址和进度，属于「结构改动」，不是「内容改动」。

### 3. 一个典型的「新知识页」是怎么构成的

一页新知识，按从上到下的阅读顺序，通常由这几段组成。每段下面配真实文件节选，并说明**它在页面上会显示成什么样**。

#### 3.1 开篇封套：思维导图 + 学习目标

2026 年 10 月起，全站新标准是把开篇的「知识结构导图 + 学习目标」一起包进一个**开篇封套**里（代码里写作 `type: "layout"`、`as: "hero"`）。下面这段来自 `src/content/math/01-集合与逻辑/01-集合的概念与表示.js` 的开头，是标准写法：

```js
export default {
  blocks: [
    {
      type: "layout",
      as: "hero",
      props: { align: "start", tone: "accent" },
      children: [
        // ---------- 知识结构导图 ----------
        {
          type: "mindmap",
          title: "知识结构导图",
          mermaid: `graph LR
      N0["集合的概念与表示"]
      N1["集合三特性"]
      N0 --> N1
      N2["确定性"]
      N1 --> N2
      N3["互异性"]
      N1 --> N3
      // ……（此处省略导图其余节点）
      N16["韦恩图法"]
      N13 --> N16`
        },
        // ---------- 学习目标 ----------
        {
          type: "objectives",
          title: "学习目标",
          items: [
            "理解集合的概念，掌握集合的三个特性：确定性、互异性、无序性",
            "掌握元素与集合的关系符号 \\(\\in\\)、\\(\\notin\\) 的使用",
            "熟记常用数集的符号表示（\\(\\mathbb{N}\\)、\\(\\mathbb{N}^*\\)、\\(\\mathbb{Z}\\)、\\(\\mathbb{Q}\\)、\\(\\mathbb{R}\\)）",
            "熟练运用列举法、描述法、韦恩图法表示集合"
          ]
        },
      ]
    },
    // ……（此处省略本页后面所有板块）
  ]
}
```

- **你会看到的**：页面最上方一整块带极浅底色的「首屏」，左边是思维导图，下面是「学习目标」清单。
- **你能改的**：`items` 里每一条学习目标；导图里每个方框的文字（`N0["…"]` 引号内）。
- **固定不要动的**：外层 `type: "layout"` / `as: "hero"` / 紧接着那一行参数 / `children: [` 这几行是**封套的固定写法**，逐字照抄即可。

> **哪些页面不用封套**：复习测验页、易错专项页这种**没有思维导图**的页面，从一页就开讲题目或易错点，**不需要**开篇封套 —— 照现有文件保持原样即可。

#### 3.2 知识讲解段

讲解概念、性质、定义之类，用 `knowledge` 板块。同页的真实节选：

```js
{
  type: "knowledge",
  title: "集合的概念",
  variant: "definition",
  paragraphs: [
    "把一些能够确定的不同的对象看成一个整体，就说这个整体是由这些对象的全体构成的集合。",
    "集合中的每个对象叫做这个集合的**元素**。"
  ]
}
```

- **页面上**：一条带标题的讲解段落。`**元素**` 这种两个星号夹住的写法会变成**加粗**。
- `variant: "definition"` 让这段显示成「定义」的样式（左侧一条细线）；不写就是普通段落。这只是样式选择，不影响内容。

#### 3.3 公式与提示

公式单独成块用 `formula`，提醒/口诀用 `warning`（警示色）或 `tip`（提示色）。真实节选（`src/content/math/02-不等式/01-不等式的基本性质.js`）：

```js
{
  type: "formula",
  title: "性质4：乘法性质（注意变号）",
  formulas: [
    "a > b, \\, c > 0 \\Rightarrow ac > bc",
    "a > b, \\, c < 0 \\Rightarrow ac < bc",
    "（不等式两边同乘正数，不等号方向不变；同乘负数，不等号方向改变）"
  ]
},

{
  type: "warning",
  text: "乘法性质是易错点！不等式两边同乘或同除一个数时，必须先判断该数的正负。若不确定符号，需分类讨论。"
}
```

- **页面上**：`formula` 显示成一框一行、居中排版的公式；`warning` 显示成醒目的警示条，`tip` 显示成较柔和的提示条。

#### 3.4 例题段

用 `example` 板块。每题含「题干 `question`」「解答过程 `solution`」「最终答案 `answer`」三部分。真实节选：

```js
{
  type: "example",
  title: "典型例题",
  items: [
    {
      title: "例题1：比较大小（作差法）",
      question: "已知 \\(a, b\\) 均为正数，比较 \\(a^2 + b^2\\) 与 \\(2ab\\) 的大小。",
      solution: "解：用作差比较法。\n\n        $$a^2 + b^2 - 2ab = (a - b)^2$$\n\n        因为对任意实数 \\(a, b\\)，都有 \\((a-b)^2 \\ge 0\\)，当且仅当 \\(a = b\\) 时……",
      answer: "答案：\\(a^2 + b^2 \\ge 2ab\\)，当且仅当 \\(a = b\\) 时等号成立。"
    },
    // ……（此处省略其余例题）
  ]
}
```

- **页面上**：题目在上，点开「查看解答」后看到解题过程与最终答案。
- 题干里换行要写成 `\n`（反斜杠 + n），不能直接敲回车换行。

#### 3.5 练习题/测验段

用 `quiz` 板块，通常放在页面靠后。真实节选（同页）：

```js
{
  type: "quiz",
  title: "练习题",
  items: [
    {
      difficulty: "basic",
      question: "下列各组对象能构成集合的是（　）\nA. 我校高一的\"帅哥\"\nB. 接近于0的数\nC. 方程 \\(x^2+1=0\\) 的实数解\nD. 比3大的数",
      answer: "答案：C。A中\"帅哥\"、B中\"接近于0\"、D中\"比3大的数\"均表述模糊。C中方程 \\(x^2+1=0\\) 无实数解，构成空集 \\(\\varnothing\\)，是合法集合。"
    }
  ]
}
```

- **页面上**：题目逐条列出，可点「查看答案」核对，做错的自动进错题本。

#### 3.6 一页速记（考前回看）

用 `summary` 板块，收尾做「考点浓缩」。真实节选：

```js
{
  type: "summary",
  title: "一页速记",
  points: [
    "集合三特性：确定性（非此即彼）、互异性（元素不重复）、无序性（与顺序无关）",
    "元素与集合的关系只有两种：\\(a \\in A\\) 或 \\(a \\notin A\\)"
    // ……（此处省略其余要点）
  ],
  formulas: [
    "\\mathbb{N}^* \\subsetneq \\mathbb{N} \\subsetneq \\mathbb{Z} \\subsetneq \\mathbb{Q} \\subsetneq \\mathbb{R}"
  ],
  mustKnow: [
    "含参数的集合必须检验互异性：如 \\(\\{a, a^2, 1\\}\\) 要先排除元素重复的 \\(a\\) 值"
  ]
}
```

- **页面上**：一张「速记卡」，`points` 是要点清单，`formulas` 是必背公式，`mustKnow` 是「最容易忘、必须记死」的结论。三者都可选，但不能全空。

**小结**：一页标准新知识页的顺序就是 —— **封套（导图 + 目标）→ 知识讲解 → 公式/提示 → 例题 → 练习 → 速记**。不是每页都齐全，但顺序基本如此。

### 4. 四个页面范例

下面四类页面覆盖了绝大多数场景。每个都给「结构骨架」和一段真实节选。

#### 范例一：新知识页

**文件**：`src/content/math/02-不等式/01-不等式的基本性质.js`

**结构骨架**（真实顺序）：

```
封套（mindmap 知识结构导图 + objectives 学习目标）
knowledge  一、实数大小的比较
formula    作差比较法 / 性质1~4 / 同向相加 …
warning    乘法性质是易错点！
table      四、性质汇总表
example    典型例题（例题1~5）
quiz       练习题
```

这段用到了「对比/汇总」的表格（真实节选）：

```js
{
  type: "table",
  title: "四、性质汇总表",
  headers: ["运算", "条件", "结论", "方向"],
  rows: [
    ["加减", "\\(a>b\\)", "\\(a\\pm c > b\\pm c\\)", "不变"],
    ["乘除（正数）", "\\(a>b, c>0\\)", "\\(ac>bc\\)", "不变"],
    ["乘除（负数）", "\\(a>b, c < 0\\)", "\\(ac < bc\\)", "改变"],
    ["同向相加", "\\(a>b, c>d\\)", "\\(a+c>b+d\\)", "不变"],
    ["取倒数", "\\(a>b>0\\)", "\\(\\frac{1}{a} < \\frac{1}{b}\\)", "改变"]
  ]
}
```

- **页面上**：一张真正的表格，`headers` 是表头，`rows` 里每个方括号是一行，元素个数要和表头一样多。

#### 范例二：复习测验页（无导图，从警示语开讲）

**文件**：`src/content/math/02-不等式/05-复习测验.js`

**结构骨架**：

```
warning   建议用时 45 分钟，满分 100 分……
quiz      一、选择题（每题 5 分，共 40 分）
quiz      二、填空题（每题 5 分，共 20 分）
example   三、解答题（共 40 分）
```

**特点**：**没有封套、没有思维导图**，开篇就是一句考试说明；按「选择题 / 填空题 / 解答题」三大段组织。真实节选：

```js
export default {
  blocks: [
    // ---------- 测验信息说明 ----------
    {
      type: "warning",
      text: "建议用时 45 分钟，满分 100 分。请先独立作答，再点击「查看答案」核对解析。"

    // ---------- 一、选择题（每题5分，共40分） ----------
    {
      type: "quiz",
      title: "一、选择题（每题 5 分，共 40 分）",
      items: [
        {
          difficulty: "basic",
          question: "若 \\(a > b\\)，则下列不等式中一定成立的是（　）\nA. \\(a^2 > b^2\\)　　B. \\(\\frac{1}{a} < \\frac{1}{b}\\)\nC. \\(a - 3 > b - 3\\)　　D. \\(ac > bc\\)（\\(c \\ne 0\\)）",
          answer: "**C**。由加法保号性，\\(a>b\\) 两边同减 3（同加 \\(-3\\)），不等号方向不变，得 \\(a-3>b-3\\)。A 错（如 \\(a=1, b=-2\\)）……"
        },
        // ……（此处省略其余选择题）
      ]
    },
    // ---------- 二、填空题（每题5分，共20分） ----------
    {
      type: "quiz",
      title: "二、填空题（每题 5 分，共 20 分）",
      items: [
        {
          difficulty: "medium",
          question: "不等式 \\(|x - 2| > 3\\) 的解集是______。",
          answer: "\\((-\\infty, -1) \\cup (5, +\\infty)\\)。\\(x-2>3\\) 或 \\(x-2<-3\\)，即 \\(x>5\\) 或 \\(x<-1\\)。"
        },
        // ……（此处省略其余填空题）
      ]
    },
    // ---------- 三、解答题（共40分） ----------
    {
      type: "example",
      title: "三、解答题（共 40 分）",
      items: [
        {
          title: "第1题（12分）",
          question: "解下列不等式：\n（1）\\(-x^2 + 2x + 3 \\ge 0\\)；\n（2）\\(|x - 2| \\le 5\\)。",
          solution: "**解：**\n（1）两边同乘 \\(-1\\) 化正并变号……",
          answer: "（1）\\(\\{x \\mid -1 \\le x \\le 3\\}\\)；（2）\\([-3, 7]\\)。"
        },
        // ……（此处省略其余解答题）
      ]
    }
  ]
}
```

- **注意**：这页的选择题把 A、B、C、D 直接写进了题干文字里（用 `\n` 换行、全角空格 `　` 分隔），所以不需要额外的 `options` 字段。**两种写法在项目里都真实存在**，详见第 5 节。

#### 范例三：易错专项页（以 errorfocus 开头）

**文件**：`src/content/math/02-不等式/06-易错专项与冲刺.js`

**结构骨架**：

```
errorfocus   高频易错专项（每个场景 = 常见错误 vs 正确思路）
quiz         冲刺拔高题（选择题，可点击作答）
```

**特点**：**没有封套、没有思维导图**，第一块就是 `errorfocus`。每一「错」有四个字段：场景 `scenario`、常见错误 `commonMistake`、正确思路 `correctApproach`、避坑提示 `tip`。真实节选：

```js
export default {
  blocks: [
    {
      type: "errorfocus",
      title: "高频易错专项",
      items: [
        {
          scenario: "不等式两边同乘（除）负数",
```

### 5. 写作技巧

#### 5.1 公式怎么写

本项目用两种公式写法，**区别在「和文字排在一行」还是「单独占一行居中」**：

| 写法 | 形式 | 用途 | 例子 |
|---|---|---|---|
| `\(...\)` | 行内公式，跟文字排在同一行 | 句子里的符号、短表达式 | `已知 \\(a > b\\)，比较大小` |
| `$$...$$` | 独立公式，单独占一行居中 | 需要突出展示的推导、结论 | `$$a^2 + b^2 - 2ab = (a - b)^2$$` |

**三个真实正例**：

1. 行内（`src/content/math/01-集合与逻辑/01-集合的概念与表示.js`）：
   ```
   掌握元素与集合的关系符号 \\(\\in\\)、\\(\\notin\\) 的使用
   ```
   → 页面上「∈、∉」就夹在文字中间显示。

2. 行内（同上，正斜杠与分数）：
   ```
   "（\\(\\mathbb{Z}\\)）"、"\\(\\frac{p}{q}\\)（\\(p,q\\in\\mathbb{Z}, q\\ne 0\\)）"
   ```
   → 显示为 ℤ、p/q（p,q∈ℤ, q≠0）。

3. 独立成行居中（`src/content/math/02-不等式/01-不等式的基本性质.js` 的例题解答里）：
   ```
   $$a^2 + b^2 - 2ab = (a - b)^2$$
   ```
   → 页面上这一整行居中放大显示成一个公式块。

**常见写错（会被校验器拦下）**：

- **公式行末尾留下一个孤立的反斜杠 `\`**。校验器专门检查这一条，会明确报出「公式区块第N行末尾有孤立反斜杠」。写公式时反斜杠总是成对使用（如 `\\in`、`\\frac{a}{b}`），**不要在行尾单留一个 `\`**。
- **`\(` 和 `\)` 必须配对**、`$$` 必须成对出现，少了任何一半公式都不会正常显示。
- 反斜杠在文件里要写**两个**（因为文件格式会吃掉一个），所以你在文件里看到的是 `\\in`，实际显示的是 `\in`。

#### 5.2 思维导图怎么写

思维导图写在 `mindmap` 板块的 `mermaid` 字段里，用一种叫 Mermaid 的图形语言。结构非常简单，就两种句式：

- **竖一个方框（节点）**：`节点编号["方框里的文字"]`
- **连一条线（箭头）**：`父节点 --> 子节点`

真实例子（`src/content/math/01-集合与逻辑/01-集合的概念与表示.js`，为便于阅读截取了开头）：

```
graph LR
      N0["集合的概念与表示"]
      N1["集合三特性"]
      N0 --> N1
      N2["确定性"]
      N1 --> N2
      N3["互异性"]
      N1 --> N3
      N4["无序性"]
      N1 --> N4
      N5["元素与集合关系"]
      N0 --> N5
```

- `graph LR` 意思是**从左到右**排列（本项目统一用这一句开头）。
- **页面上**：它会自动画成一棵从左向右展开的树状图。

**改动注意**：

- **节点编号（N0、N1……）不能重复**，每新增一个方框就换一个新编号（顺着往下 N17、N18……）。
- 方框文字**要放在英文双引号里**：`N20["一句话"]`。引号内可以写中文，但**不要在里面再塞一个双引号**。
- 连线的两端必须是**已经出现过的节点编号**；箭头统一写 `-->`。
- 只改文字时，最稳妥的做法是**只动引号里的字**，编号和箭头一行都别碰。
- 有些页面把导图写成「一行到底、用 `\n` 换行」，有些写成「分成多行」。**两种都能正常显示**，你只要保持所在文件原本的写法即可。

#### 5.3 测验题怎么设计

题目分两种形态，按需要选：

**形态 A：问答式（判断 / 填空 / 简答，不可点选）**

```js
{
  difficulty: "basic",
  question: "判断：\\(\\{1, 1, 2\\}\\) 是一个合法的集合表示。",
  answer: "**错误。**根据集合的**互异性**，集合中的元素不能重复。\\(\\{1, 1, 2\\}\\) 应化简为 \\(\\{1, 2\\}\\)。"
}
```

只要有 `question` 和 `answer` 就能成立，页面上学生点「查看答案」核对。

**形态 B：选择题（可点选、有即时对错反馈）**

```js
{
  type: "single", difficulty: "sprint",
  question: "已知 \\(a > b\\)，\\(c > d\\)，则下列不等式一定成立的是（　）",
  options: ["\\(a - c > b - d\\)", "\\(ac > bd\\)", "\\(a + c > b + d\\)", "\\(\\frac{a}{c} > \\frac{b}{d}\\)"],
  correctIndex: 2,
  answer: "**C**。同向不等式**可以相加**……"
}
```

字段说明：

| 字段 | 填什么 | 备注 |
|---|---|---|
| `type` | `"single"` 单选 / `"judge"` 判断 / `"fill"` 填空 | 选择题填 `single` |
| `question` | 题干 | 换行写 `\n`，可用 LaTeX、`**加粗**`、`` `行内代码` `` |
| `options` | 选项数组，按顺序排列 | 可带也可不带「A.」前缀——两种写法项目里都有 |
| `correctIndex` | 正确选项的**序号** | **从 0 开始数**！第 1 个选项是 0，第 2 个是 1…… |
| `answer` | 答案 + 解析 | 页面「查看答案」里显示 |
| `difficulty` | 难度标签 | 见 5.4 |

> **最容易栽的坑**：`correctIndex` **从 0 开始**。上面的例子 `correctIndex: 2` 对应的是第 **3** 个选项「\\(a + c > b + d\\)」，也就是答案里的 **C**。写错这个数，学生点对的选项会被判错。校验器会检查它是否越界（比如选项只有 4 个却写了 4）。

**干扰项设计建议**：

- 每个错误选项都要**对应一个真实会犯的错**，而不是随便凑数。例如上面拔高题里的 A 项 `\(a - c > b - d\)` 就是「以为同向不等式能相减」这个典型错误。
- 优选用**本页刚讲过的易错点**来造干扰项，让选择题同时承担「复习巩固」的作用。
- 题目和答案里可以用 `**加粗**` 标出关键结论（如 `**C**。`、`**错误。**`）。

#### 5.4 标签与难度字段怎么填

**难度 `difficulty`**（只允许这四种写法，写错会被校验器拦下）：

| 取值 | 含义 | 用在哪儿 |
|---|---|---|
| `"basic"` | 基础 | 概念题、直接套公式的题 |
| `"medium"` | 中等 | 需要一两步推理 |
| `"advanced"` | 提高 | 综合应用、易错型 |
| `"sprint"` | 冲刺 | 拔高题、模拟卷 |

（`difficulty` 可以写，但**不是必填**；写了就必须是上面四个之一。）

**板块标题 `title`**：几乎每种板块都能带一个 `title`。它是**页面上的小标题**，例如 `title: "一、选择题（每题 5 分，共 40 分）"`、`title: "典型例题"`。建议保持和现有页面一致的编号习惯，方便学生对照。

**页面标题与副标题**：注意 —— 页面顶部的标题、副标题**不在页面文件里**，而在 `site.js` 的清单里（见第 2 节）。改标题去改 `site.js`，不要在页面文件里另写一遍。

### 6. 我改完后会发生什么（工作流程）

#### 从「改文件」到「学生看到」

```
① 你修改 / 新增页面文件（只动引号里的文字）
        ↓
② 运行自检命令：npm run validate:content
        ↓
③ 通过 ✅ → 提交给开发侧（或由工具合并到主版本）
        ↓
④ 开发侧重新生成并发布 → 学生端看到新内容
```

#### 第 ② 步的校验会帮你拦下哪些错

`npm run validate:content` 会逐页检查，常见拦截项包括：

- **板块种类写错**：`type:` 写了不存在的名字；
- **缺必填内容**：如讲解块没有 `paragraphs`、题目没有 `question` 或 `answer`、提示块 `text` 是空的；
- **选择题的 `correctIndex` 越界**，或「有正确答案序号却没写选项」；
- **公式行末尾有孤立反斜杠**（见 5.1）；
- **表格没有 `rows`**；**思维导图没有 `mermaid`**；
- **页面文件里多写了不该写的字段**（如 `id`、`title`、`subject` 等——这些由 `site.js` 统一提供，页面文件里出现即报错）；
- **目录里有「没登记」的孤儿文件**：新建了页面文件却忘了在 `site.js` 的 `files` 里登记；
- **登记了但文件不存在**：`site.js` 里写了某个 `name`，磁盘上却没有对应文件。

看到 **✅ 全部通过！** 才算过关；有 **❌** 就按提示逐条修。

#### 教育专家侧自检清单（提交前过一遍）

1. **我只动了引号里的文字吗？** 括号 `{}`、方括号 `[]`、`type:`、逗号都没有被误删或误加。
2. **公式配对了吗？** 每一个 `\(` 都有对应的 `\)`，每一个 `$$` 都成对，且**没有公式行以孤立反斜杠结尾**。
3. **选择题的 `correctIndex` 数对了吗？** 记住从 0 开始，并和 `answer` 里写的答案字母一致。
4. **换行都用 `\n` 吗？** 题干、解答里没有直接敲回车造成的断行。
5. **思维导图编号没重复、箭头都对上号了吗？** 新增方框用的是没出现过的新编号。
6. **标题改在 `site.js` 里了吗？** 页面顶部的标题/副标题只认 `site.js`，没在页面文件里重复写。
7. **新增页面是加在清单末尾吗？** 没有插到中间打乱顺序（顺序即地址与进度）。
8. **跑过 `npm run validate:content` 且显示 ✅ 了吗？**

### 学习页文件长什么样

一个学习页就是一个文件，名字写在一对引号里，里面按顺序列出这个页面的所有内容块：

```js
export default {
  blocks: [
    // 一个接一个地写内容块，看到的顺序 = 这里写的顺序
  ]
}
```

三条最基本的规定：

1. **每个内容块都必须写 `type`**（比如 `type: "knowledge"`），它决定这一块以什么样子出现。
2. **不要在页面文件里写页面自己的信息**：`id`、`unitNum`、`subject`、`title`、`subtitle`、`icon`
   这六个字段由系统自动生成。写进内容文件会被检查直接报错。
3. 文字里的公式用 LaTeX 写法（行内公式写 `\\(...\\)`），加粗用 `**加粗**`。这两点在下面很多区块里都能用。

### 1. 区块速查表

| `group` | 分组 | 把相关区块圈成一组（可为可折叠） | 把「核心概念」框成一段 |
| `layout` | 布局 | 控制版面的高级排法（首屏强调、出血、侧轨等） | 页面首屏、需要特殊版式时 |
| `steps` | 步骤条 | 把操作流程编成有先后顺序的编号步骤 | 操作规范、搭建流程 |
| `summary` | 一页速记 | 考前回看卡：速记要点 / 必背公式 / 必记结论 | 页面最后，收尾 |
| `compare` | 对比 | 把两个易混概念按维度并排中性对照 | 区分易混概念（如全称 vs 特称） |
| `vocab` | 术语卡 | 一个术语一张卡：术语 / 释义 / 例句 / 备注 | 文言实词、专业名词 |
| `code` | 代码 | 等宽展示一段命令或程序 | 计算机类命令、配置 |
| `cloze` | 挖空默写 | 把句子里的空位藏起来、点一下揭晓 | 古诗文默写、公式填写 |

### 2. 每种区块的详细参考

> 说明：所有区块都可以写 `title`（区块标题，选填）。写出标题会让这一块在目录里更清楚。下表不再重复列 `title`，只在有特别说明时单独讲。

#### 2.1 思维导图 `mindmap`

**用途**：用一张节点关系图，先给学习者一张「这一页讲什么」的全景地图。

**字段表**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"mindmap"` | 声明这是一个思维导图块 |
| `title` | 选填 | 文字 | 无 | 区块标题，一般写「知识结构导图」 |
| `mermaid` | **必填** | 文字 | 不能为空 | 导图的画法文本，用的是 Mermaid 图语法 |

**最简示例**（摘自 `src/content/chinese/02-现代文阅读/01-记叙文阅读.js`）

```js
{
  type: "mindmap",
  title: "知识结构导图",
  mermaid: "graph LR\n  N0[\"记叙文阅读\"]\n  N1[\"六要素\"]\n  N0 --> N1\n  N2[\"时间地点\"]\n  N1 --> N2"
}
```

如果导图节点较多，也可以像 `src/content/math/01-集合与逻辑/01-集合的概念与表示.js` 一样，用一段多行文字（反引号包裹）来写，可读性更好：

```js
{
  type: "mindmap",
  title: "知识结构导图",
  mermaid: `graph LR
      N0["集合的概念与表示"]
      N1["集合三特性"]
      N0 --> N1
      N2["确定性"]
      N1 --> N2
      N3["互异性"]
      N1 --> N3`
}
```

**常见错误**

- ❌ 只写 `title` 不写 `mermaid` → ✅ 必须给出导图画法文本，否则检查报「思维导图区块缺少 mermaid 源码」。
- ❌ 节点名的引号没配对、箭头写成 `->` → ✅ Mermaid 有固定语法（`A --> B`），引号必须成对，否则图画不出来。

#### 2.2 学习目标 `objectives`

**用途**：在页面开头列出这一页要达成的学习目标，通常 3～5 条。

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"objectives"` | 声明这是学习目标块 |
| `title` | 选填 | 文字 | 无 | 区块标题，默认显示「学习目标」 |
| `items` | **必填** | 文字清单 | 至少 1 条，条目不能为空 | 每条是一个学习目标，逐条会显示成一个圆点行 |

**最简示例**（摘自 `src/content/computer/01-职业素养/01-计算机操作规范.js`）

```js
{
  type: "objectives",
  title: "学习目标",
  items: [
    "了解计算机操作职业道德的基本要求，树立规范操作意识",

    "掌握正确的开关机顺序与重启操作方法"
  ]
}
```

**常见错误**

- ❌ `items: []` 或完全不写 `items` → ✅ 至少写一条，否则检查报「目标区块缺少 items」。
- ❌ 清单里混入空字符串（`""` 或只有空格的一行）→ ✅ 删掉空条，检查会报「目标区块存在空 items 元素」。

#### 2.3 知识点 `knowledge`

**用途**：讲解概念、性质、方法的正文块，是整页用得最多的一块。

**字段表**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"knowledge"` | 声明这是知识点块 |
| `title` | 选填 | 文字 | 无 | 区块标题（如「集合的概念」） |
| `paragraphs` | **必填** | 文字清单 | 每条一段 | 每一段单独一行，支持 `**加粗**` 与 LaTeX 公式 |
| `variant` | 选填 | 文字 | `plain` / `definition` / `aside` 三选一 | 换一种呈现风格（见下） |

`variant` 的三个取值：

- `plain`（或不写）—— 默认正文样式；
- `definition` —— 定义型，左侧一条细线，用来突出「定义」；
- `aside` —— 补充说明，字号和颜色都降一级，用来放旁注。

**最简示例**（摘自 `src/content/computer/01-职业素养/01-计算机操作规范.js`）

```js
{
  type: "knowledge",
  title: "计算机操作职业道德",
  paragraphs: [
    "**遵守操作规程：**严格按照计算机及机房设备的操作规程进行操作，不擅自拆卸、改装设备。",
    "**爱护设备设施：**轻拿轻放，操作设备力度适合，不敲击键盘、不摔打鼠标。",
    "**诚实守信：**不盗用他人账号，不破坏他人文件，尊重知识产权。"
  ]
}
```

**完整示例（用 definition 变体突出定义）**（摘自 `src/content/math/01-集合与逻辑/01-集合的概念与表示.js`）

```js
{
  type: "knowledge",
  title: "集合的概念",
  variant: "definition",
  paragraphs: [
    "把一些能够确定的不同的对象看成一个整体，就说这个整体是由这些对象的全体构成的集合。",
    "集合中的每个对象叫做这个集合的**元素**。"
  ]
}
```

**常见错误**

- ❌ 不写 `paragraphs` → ✅ 检查报「知识点区块缺少 paragraphs」。
- ❌ `variant` 写成 `"aside"` 以外的自造值（如 `"note"`）→ ✅ 只能是 `plain` / `definition` / `aside`。
- ❌ 想写多段却挤进一条里、中间用 `\n` 换行 → ✅ 拆成多个清单条目，一段一条更清晰。

#### 2.4 公式 `formula`

**用途**：把核心公式单独成块、居中突出展示。

**字段表**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"formula"` | 声明这是公式块 |
| `title` | 选填 | 文字 | 无 | 区块标题（如「作差比较法」） |
| `formulas` | **必填** | 文字清单 | 每条一行公式，**行尾不能是反斜杠** | 每条会显示成一行居中公式 |

> ⚠️ 关于字段名：项目里有些早期文件用了近义写法 `lines`（如 `src/content/math/01-集合与逻辑/01-集合的概念与表示.js`），检查同样接受。**新写的内容请统一用 `formulas`**（与权威定义一致）。

**最简示例**（摘自 `src/content/math/02-不等式/01-不等式的基本性质.js`）

```js
{
  type: "formula",
  title: "作差比较法",
  formulas: ["a - b > 0 \\iff a > b", "a - b = 0 \\iff a = b", "a - b < 0 \\iff a < b"]
}
```

**完整示例（含说明文字的公式行）**（摘自 `src/content/math/01-集合与逻辑/06-量词与命题否定.js`）

```js
{
  type: "formula",
  title: "命题否定规则",
  formulas: [
    "① \\(\\neg\\big(\\forall x \\in M, p(x)\\big) \\iff \\exists x \\in M, \\neg p(x)\\)（全称命题的否定是特称命题）",
    "② \\(\\neg\\big(\\exists x \\in M, p(x)\\big) \\iff \\forall x \\in M, \\neg p(x)\\)（特称命题的否定是全称命题）"
  ]
}
```

**常见错误**

- ❌ 公式行**结尾**是一个孤立的反斜杠（如 `"... \\"` 或 `"\frac{1}{2}\"`）→ ✅ 补全这一条公式，反斜杠后必须还有内容，否则公式会变成红色源码、检查报「第 N 行末尾有孤立反斜杠」。
- ❌ 不写 `formulas`（也没有 `lines`）→ ✅ 检查报「公式区块缺少 formulas」。
- ❌ 把整段讲解文字塞进公式块 → ✅ 公式块只放公式，讲解请用 `knowledge`。

#### 2.5 表格 `table`

**用途**：把多项内容排成对照表，例如数集符号表、开关机顺序表、分类表。

**字段表**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"table"` | 声明这是表格块 |
| `title` | 选填 | 文字 | 无 | 表格标题 |
| `headers` | **必填** | 文字清单 | 一般与列数一致 | 表头文字，一行一格 |
| `rows` | **必填** | 文字清单的清单 | 每一行是一个清单 | 表体：每一行由若干格文字组成 |

**最简示例**（摘自 `src/content/computer/01-职业素养/01-计算机操作规范.js`）

```js
{
  type: "table",
  title: "开关机顺序对照表",
  headers: ["操作", "顺序", "注意事项"],
  rows: [
    ["开机", "先开显示器，再开主机", "先开外设，再开主机电源"],
    ["关机", "先关主机，再关显示器", "使用系统\"开始→关机\"，不直接按电源键强行关机"]
  ]
}
```

**完整示例（含 LaTeX 公式单元格）**（摘自 `src/content/math/01-集合与逻辑/01-集合的概念与表示.js`）

```js
{
  type: "table",
  title: "常用数集及符号",
  headers: ["符号", "名称", "含义"],
  rows: [
    ["\\(\\mathbb{N}\\)", "非负整数集（自然数集）", "\\(0, 1, 2, 3, \\cdots\\)"],
    ["\\(\\mathbb{N}^*\\) 或 \\(\\mathbb{N}^+\\)", "正整数集", "\\(1, 2, 3, 4, \\cdots\\)"],
    ["\\(\\mathbb{Z}\\)", "整数集", "\\(\\cdots, -2, -1, 0, 1, 2, \\cdots\\)"]
  ]
}
```

**常见错误**

- ❌ 不写 `rows` → ✅ 检查报「表格区块缺少 rows」；`rows` 必须是「一行一个清单」的嵌套写法。
- ❌ 某一行格子数与表头对不上 → ✅ 每行格子数保持一致，表格才整齐（检查不会逐格报警，但显示会错位）。
- ❌ `rows` 写成一段普通文字 → ✅ 必须是清单套清单（`[["...", "..."]]`）。

#### 2.8 例题 `example`

**用途**：展示带解答过程的典型例题，题干先显示、解答与答案默认折叠，方便先思考后看解。

**字段表（区块本身）**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"example"` | 声明这是例题块 |
| `title` | 选填 | 文字 | 无 | 区块标题，默认显示「典型例题」 |
| `items` | **必填** | 例题清单 | 至少 1 道 | 每道例题是一个小对象 |
| `variant` | 选填 | 文字 | `full` / `compact` | 完整或紧凑显示（项目现用内容均为默认 `full`） |

**每道例题（items 里的一项）的字段**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `title` | 选填 | 文字 | 无 | 例题小标题，如「例题1：⋯⋯」 |
| `question` | **必填** | 文字 | 不能为空 | 题干 |
| `solution` | 选填 | 文字 | 与 `answer` 不能同时为空 | 解答过程 |
| `answer` | 选填 | 文字 | 与 `solution` 不能同时为空 | 最终答案 |
| `difficulty` | 选填 | 文字 | 只能填四个难度值之一 | 难度标签，会显示成小色签 |

**最简示例**（摘自 `src/content/computer/01-职业素养/01-计算机操作规范.js`）

```js
{
  type: "example",
  title: "典型例题",
  items: [
    {
      title: "例题1：开关机顺序判断",
      question: "小张准备开始上机操作，请写出正确的开机顺序，并说明理由。",
      solution: "**解：**\n正确的开机顺序是：**先开显示器，再开主机**。\n理由：先开外设可以避免主机启动时外设尚未就绪导致的检测异常，也能保护设备。关机时顺序相反：先关主机，再关显示器。",
      answer: "开机：先开显示器再开主机；关机：先关主机再关显示器。"
    }
  ]
}
```

**完整示例（带难度标签）**（摘自 `src/content/computer/03-计算机网络技术/02-网络拓扑搭建.js`）

```js
{
  type: "example",
  title: "典型例题",
  items: [
    {
      title: "例题1：拓扑结构判断",
      difficulty: "basic",
      question: "某机房所有 PC 都连接到一台中心交换机上，这种拓扑结构是（　）\nA. 总线型　B. 星型　C. 环型　D. 网状",
      solution: "**解：**\n所有设备连接到中心交换机，属于星型拓扑。中心交换机是核心节点，PC 之间的通信都经过它。",
      answer: "答案：B。星型拓扑。"
    }
  ]
}
```

**常见错误**

- ❌ 某道例题不写 `question` → ✅ 检查报「例题[N] question 为空」。
- ❌ 某道例题 `solution` 和 `answer` 都不写 → ✅ 至少要写一个（只有答案、没有过程也可以），否则检查报「solution 与 answer 均为空」。
- ❌ `difficulty` 写成 `"简单"` / `"hard"` → ✅ 只能用 `basic` / `medium` / `advanced` / `sprint`（见附录 B）。
- ❌ 题干里想换行却直接敲了回车 → ✅ 在文字里用 `\n` 表示换行。

#### 2.9 题目 `quiz`

**用途**：快速检测 / 随堂练习。可让学习者点选项自测、点「查看答案」核对，但**不判对错、不打分**。适合放随堂检测与课后练习题。

**字段表（区块本身）**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"quiz"` | 声明这是题目块 |
| `title` | 选填 | 文字 | 无 | 区块标题，如「快速检测」「练习题」 |
| `items` | **必填** | 题目清单 | 至少 1 题 | 每道题是一个小对象 |

**每道题（items 里的一项）的字段**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `question` | **必填** | 文字 | 不能为空 | 题干 |
| `answer` | **必填** | 文字 | 不能为空 | 答案与解析 |
| `type` | 选填 | 文字 | `single` / `judge` / `fill` | 题型：单选 / 判断 / 填空；选填，不写也能显示 |
| `options` | 选填 | 文字清单 | 有 `correctIndex` 时必须写 | 选择题的各个选项 |
| `correctIndex` | 选填 | 数字 | 有选项时，从 **0** 开始计数 | 正确选项是第几个 |
| `difficulty` | 选填 | 文字 | 只能填四个难度值之一 | 难度标签 |

> ⚠️ **最重要的一条**：`correctIndex` 从 **0** 开始数。第一个选项是 `0`，第二个是 `1`，第三个是 `2`，第四个是 `3`。写 `4` 会越界报错。

**最简示例（判断题，不含选项）**（摘自 `src/content/computer/01-职业素养/01-计算机操作规范.js`）

```js
{
  type: "quiz",
  title: "快速检测",
  items: [
    {
      difficulty: "basic",
      type: "judge",
      question: "开机时应先开主机，再开显示器。",
      answer: "**错误。**开机应先开显示器等外设，再开主机；关机顺序相反。"
    }
  ]
}
```

**完整示例（单选题，带选项与 correctIndex）**（摘自 `src/content/computer/01-职业素养/01-计算机操作规范.js`）

```js
{
  type: "quiz",
  title: "练习题",
  items: [
    {
      difficulty: "medium",
      type: "single",
      question: "关于键盘鼠标使用，下列说法正确的是（　）",
      options: ["A. 击键越重速度越快", "B. 双手食指应放在 F 和 J 键上", "C. 鼠标可以随意摔打", "D. 坐姿与操作效率无关"],
      correctIndex: 1,
      answer: "答案：B。双手食指放在 F 和 J 键的定位凸点上，是标准指法的基础。"
    }
  ]
}
```

（上例中正确答案是第二个选项 B，所以 `correctIndex: 1`。）

**常见错误**

- ❌ 把 `correctIndex` 当成「第几个」从 1 开始写 → ✅ 从 **0** 开始：第一个选项是 `0`。
- ❌ 写了 `correctIndex` 却没写 `options` → ✅ 两者要么都不写（纯文字题），要么一起写，检查报「有 correctIndex 但缺少 options」。
- ❌ `correctIndex` 超出选项个数（4 个选项却写 `4` 或更大）→ ✅ 取值范围是 0 到「选项数 − 1」，否则检查报「correctIndex 越界」。
- ❌ 题干或答案留空 → ✅ 检查报「question 为空」或「answer 为空」。
- ❌ `type` 写成 `"choice"` / `"选择"` → ✅ 选择题要写 `single`。
- ❌ `difficulty` 用了白名单外的词 → ✅ 只能用 `basic` / `medium` / `advanced` / `sprint`。

#### 2.11 易错专项 `errorfocus`

**用途**：把高频易错点做成「场景 → 常见错误 → 正确思路」的对照，强化避坑。

**字段表（区块本身）**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"errorfocus"` | 声明这是易错专项块 |
| `title` | 选填 | 文字 | 无 | 区块标题，默认显示「易错专项」 |
| `items` | **必填** | 易错项清单 | 至少 1 项 | 每个易错点是一个小对象 |

**每个易错项（items 里的一项）的字段**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `scenario` | **必填** | 文字 | 无 | 易错场景（在什么情况下容易错） |
| `commonMistake` | **必填** | 文字 | 无 | 常见错误（错在哪） |
| `correctApproach` | **必填** | 文字 | 无 | 正确思路（应该怎么做） |
| `tip` | 选填 | 文字 | 无 | 避坑提示，会显示成一个小提示条 |

**完整示例**（摘自 `src/content/math/02-不等式/06-易错专项与冲刺.js`）

```js
{
  type: "errorfocus",
  title: "高频易错专项",
  items: [
    {
      scenario: "不等式两边同乘（除）负数",
      commonMistake: "由 \\(-2x > 4\\) 直接得 \\(x > -2\\)，忘记不等式两边同乘（除）负数时**必须改变不等号方向**。",
      correctApproach: "两边同除以 \\(-2\\)（负数）要变号：\\(-2x > 4 \\Rightarrow x < -2\\)。口诀：**乘除负数，不等号反向**。",
      tip: "见到系数为负，先想『变号』；可用特殊值 \\(x = -3\\) 代入检验解集是否正确。"
    }
  ]
}
```

**常见错误**

- ❌ 不写 `items` → ✅ 检查报「易错专项区块缺少 items」。
- ❌ 每个易错项漏写 `scenario` / `commonMistake` / `correctApproach` 中的任意一个 → ✅ 三项都要写（`tip` 可省）。检查会提示哪一项缺失。
- ❌ 想表达「中性对照、不分对错」却用本区块 → ✅ 那种情况请改用 `compare`（对比），本区块的语义是「错 → 对」。

#### 2.13 模拟卷 `exam`

**用途**：一整张带倒计时、按分计分、交卷后自动评分并生成错题回顾的模拟卷。一页通常只放一张。

**字段表（区块本身）**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"exam"` | 声明这是模拟卷块 |
| `title` | 选填 | 文字 | 无 | 卷子标题，默认显示「模拟卷」 |
| `duration` | 选填 | 数字 | 单位：分钟 | 考试时长，不写默认 90 分钟 |
| `totalScore` | 选填 | 数字 | 无 | 满分，不写默认 100 |
| `passingScore` | 选填 | 数字 | 无 | 及格分，不写默认 60 |
| `items` | **必填** | 题目清单 | 至少 1 题 | 每道题是一个小对象 |

**每道题（items 里的一项）的字段**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `question` | **必填** | 文字 | 不能为空 | 题干 |
| `answer` | **必填** | 文字 | 不能为空 | 答案与解析 |
| `type` | 选填 | 文字 | `single` / `judge` / `fill` / `solve` | 题型：单选 / 判断 / 填空 / **解答**（`solve` 是模拟卷独有的） |
| `options` | 选填 | 文字清单 | 有 `correctIndex` 时必须写 | 选择题选项 |
| `correctIndex` | 选填 | 数字 | 从 **0** 开始 | 正确选项是第几个（规则同 `quiz`） |
| `score` | 选填 | 数字 | 无 | 本题分值，会显示成「(N 分)」 |
| `difficulty` | 选填 | 文字 | 只能填四个难度值之一 | 难度标签 |

**完整示例（节选）**（摘自 `src/content/math/12-模拟冲刺/02-真题模拟卷一.js`）

```js
{
  type: "exam",
  title: "数学真题模拟卷（一）",
  duration: 120,
  totalScore: 150,
  passingScore: 90,
  items: [
    {
      type: "single", difficulty: "basic", score: 5,
      question: "已知集合 \\(A = \\{1, 2, 3\\}\\)，\\(B = \\{2, 3, 4\\}\\)，则 \\(A \\cup B =\\)（　）",
      options: ["\\(\\{1, 2, 3, 4\\}\\)", "\\(\\{2, 3\\}\\)", "\\(\\{1, 4\\}\\)", "\\(\\{1, 2, 3\\}\\)"],
      correctIndex: 0,
      answer: "**A**。\\(A \\cup B = \\{1,2,3\\} \\cup \\{2,3,4\\} = \\{1,2,3,4\\}\\)。"
    }
  ]
}
```

**常见错误**

- ❌ 不写 `items` → ✅ 检查报「模拟卷区块缺少 items」。
- ❌ 选择题写了 `correctIndex` 却没写 `options`、或 `correctIndex` 越界 → ✅ 同 `quiz` 的规则（从 0 开始、不超出选项数）。
- ❌ 题干或答案留空 → ✅ 检查报「question 为空」/「answer 为空」。
- ❌ 分值不写 `score` → ✅ 不会报错，但每题会显示「(0 分)」，建议逐题写清分值。
- ❌ 在普通学习页里用 `exam` 放几道随堂题 → ✅ 随堂题请用 `quiz`，`exam` 只用于整卷。

#### 2.14 多栏 `columns`

**用途**：把内容并排分成 2～3 栏，用于左右对照摆放两组内容（如左边放公式、右边放表格）。窄屏会自动降成一栏。

**字段表**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"columns"` | 声明这是多栏块 |
| `title` | 选填 | 文字 | 无 | 区块标题 |
| `cols` | 选填 | 数字 | 只能填 `2` 或 `3` | 桌面端列数，不写默认 2 |
| `gap` | 选填 | 文字 | `normal` / `tight` | 列间距：正常 / 紧凑 |
| `items` | **必填** | 多个内容块清单 | 每栏是一个内容块清单 | 每一栏里放哪些区块 |

**完整示例**（摘自 `src/content/math/01-集合与逻辑/01-集合的概念与表示.js`）

```js
{
  type: "columns",
  cols: 2,
  gap: "normal",
  items: [
    [
      {
        type: "formula",
        title: "元素与集合关系",
        formulas: ["\\(a \\in A\\)：元素 \\(a\\) 属于集合 \\(A\\)"]
      },
      {
        type: "tip",
        text: "记忆口诀：\\(\\mathbb{N}\\) 包含 0，\\(\\mathbb{N}^*\\) 不含 0。"
      }
    ],
    [
      {
        type: "table",
        title: "常用数集及符号",
        headers: ["符号", "名称", "含义"],
        rows: [["\\(\\mathbb{N}\\)", "非负整数集（自然数集）", "\\(0, 1, 2, 3, \\cdots\\)"]]
      }
    ]
  ]
}
```

（上方两栏结构取自 `src/content/math/01-集合与逻辑/01-集合的概念与表示.js`，为便于阅读省略了部分条目；原文件公式块用的是 `lines`，此处的 `formulas` 是推荐写法，两者效果相同。）

**常见错误**

- ❌ `items` 写成「一栏里直接放几个区块」而不是「每栏各是一个清单」→ ✅ 必须是「清单套清单」：外层每项代表一栏，内层是这一栏里的区块。
- ❌ 写了 `cols: 2` 却只给了 1 栏内容 → ✅ 栏数与实际栏数要对应，否则会空出一栏。
- ❌ `cols` 写 `4` 或 `gap` 写 `loose` → ✅ 多栏只支持 `2`/`3` 两列和 `normal`/`tight` 两种间距。

#### 2.15 分组 `group`

**用途**：把若干相关区块圈成一组，视觉上归到同一段。有两种形态：`band`（顶部一条细线的分组带）和 `collapse`（可点标题折叠/展开）。

**字段表**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"group"` | 声明这是分组块 |
| `title` | 选填 | 文字 | 无 | 分组标题（分组带一般要写） |
| `variant` | 选填 | 文字 | `band` / `collapse` | 分组形态，不写默认 `band` |
| `collapsed` | 选填 | 是/否 | 仅在 `collapse` 时有效 | 初始是否折叠，不写默认不折叠 |
| `items` | 选填 | 内容块清单 | 无 | 组里包含的区块 |

**完整示例**（摘自 `src/content/math/01-集合与逻辑/01-集合的概念与表示.js`）

```js
{
  type: "group",
  variant: "band",
  title: "核心概念",
  items: [
    {
      type: "knowledge",
      title: "集合的概念",
      variant: "definition",
      paragraphs: ["把一些能够确定的不同的对象看成一个整体，就说这个整体是由这些对象的全体构成的集合。"]
    },
    {
      type: "warning",
      text: "互异性是常考考点！遇到含参数的集合，必须检验元素是否互异。"
    }
  ]
}
```

**常见错误**

- ❌ `variant` 写成 `"collapse"` 却把 `collapsed` 写成了文字 `"true"` → ✅ `collapsed` 是「是/否」值，直接写 `true`（不加引号）。
- ❌ 把分组当内容块，空着 `items` 只写标题 → ✅ 分组是架子，里面要真正放区块才有意义。
- ❌ 在分组里再套很多层分组 → ✅ 尽量避免过深嵌套，层级太深可读性会变差。

#### 2.16 布局 `layout`

**用途**：控制版面的高级排法。首屏强调、出血加宽、侧轨等特殊版面都靠它。日常写页面时，最基本的用法是「首屏强调」（`hero`）和「网格」（`grid`）。

**字段表**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"layout"` | 声明这是布局块 |
| `as` | **必填** | 文字 | 六选一，见下 | 用哪种排法 |
| `props` | 选填 | 对象 | 键与取值受 `as` 限制，见下 | 这种排法的参数 |
| `children` | **必填** | 内容块清单 | 至少要有内容 | 排进去的区块 |

**`as` 六种排法及各自允许的参数**

| `as` 取值 | 含义 | 允许的参数 |
| --- | --- | --- |
| `hero` | 首屏强调 | `align`：`start`/`center`；`tone`：`plain`/`accent` |
| `grid` | 网格 | `cols`：`2`/`3`/`4`；`gap`：`normal`/`tight`/`loose` |
| `stack` | 纵向堆叠 | `gap`：`normal`/`tight`/`loose` |
| `split` | 主次分栏 | `ratio`：`1:1`/`1:2`/`2:1`/`1:3`/`3:1`；`gap`：`normal`/`tight`/`loose` |
| `bleed` | 出血（内容加宽到边缘） | `side`：`start`/`end`/`both`；`width`：`wide`/`full` |
| `rail` | 侧轨 | `side`：`start`/`end`；`width`：`sm`/`md`；`sticky`：`true`/`false`；`gap`：`normal`/`tight`/`loose` |

**最简示例（首屏强调）**（摘自 `src/content/chinese/02-现代文阅读/01-记叙文阅读.js`）

```js
{
  type: "layout",
  as: "hero",
  props: { align: "start", tone: "accent" },
  children: [
    {
      type: "mindmap",
      title: "知识结构导图",
      mermaid: "graph LR\n  N0[\"记叙文阅读\"]\n  N1[\"六要素\"]\n  N0 --> N1\n  N2[\"时间地点\"]\n  N1 --> N2"
    },
    {
      type: "objectives",
      title: "学习目标",
      items: [
        "准确把握记叙文的六要素，理清文章的叙事脉络与情节发展",
        "辨析顺叙、倒叙、插叙、补叙等叙事顺序，理解其表达效果"
      ]
    }
  ]
}
```

**完整示例（网格：两栏紧凑排）**（摘自 `src/content/chinese/01-语言文字运用/03-标点符号.js`）

```js
{
  type: "layout",
  as: "grid",
  props: { cols: 2, gap: "tight" },
  children: [
    {
      type: "warning",
      text: "顿号使用的常见错误：\n\n      ① 并列的词语后有\"啊\"\"呀\"等语气词时，不用顿号用逗号。\n\n      ② 并列词语之间有连词\"和、与、及、或\"等时，连词前不用顿号。\n\n      ③ 概数之间不用顿号：三四天（不是\"三、四天\"）。"
    }
  ]
}
```

（原文件的网格里共 4 个 `warning`，此处只列第一个；`text` 里的换行用 `\n` 表示，缩进空格是原文件的真实写法。）

**常见错误**

- ❌ 少写 `as` 或 `children` → ✅ 检查报「布局区块缺少 as」/「布局区块缺少 children」。
- ❌ `as` 写成 `"row"` 之类的自定义名 → ✅ 只能是 `grid`/`stack`/`split`/`hero`/`bleed`/`rail` 六种。
- ❌ 给排法配了它不支持的参数（如给 `hero` 写 `cols`）→ ✅ 检查报「布局原语 hero 不支持参数 cols」。
- ❌ 参数取值越界（如 `grid` 的 `cols: 5`、`split` 的 `ratio: "1:4"`）→ ✅ 检查报「取值非法」，请按上表取值。
- ❌ 布局一层套一层、越套越深 → ✅ 嵌套最深层数上限是 **8 层**，超过检查报「布局嵌套超过上限」。

#### 2.17 步骤条 `steps`

**用途**：把有先后顺序的操作流程编成编号步骤（序号由系统自动生成，**内容里不要自己写「1.」「2.」**）。

**字段表（区块本身）**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"steps"` | 声明这是步骤条块 |
| `title` | 选填 | 文字 | 无 | 区块标题 |
| `items` | **必填** | 步骤清单 | 至少 1 步 | 每步是一个小对象 |

**每一步（items 里的一项）的字段**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `title` | **必填** | 文字 | 不能为空 | 这一步做什么（一句话） |
| `content` | 选填 | 文字 | 不写则省略 | 这一步的详细说明，支持加粗与公式 |

**完整示例**（摘自 `src/content/computer/03-计算机网络技术/02-网络拓扑搭建.js`）

```js
{
  type: "steps",
  title: "考试拓扑搭建步骤",
  items: [
    { title: "放置设备", content: "按拓扑图将交换机、路由器、PC、服务器拖入工作区，摆放位置合理。" },
    { title: "修改标识", content: "双击设备修改名称，如交换机命名为 SWA、SWB，路由器命名为 RA、RB。" },
    { title: "连接设备", content: "选择正确线缆，按端口号逐一连接，PC 连交换机、交换机连路由器。" },
    { title: "核对检查", content: "对照拓扑图检查设备数量、连线、端口号是否完全一致。" },
    { title: "保存文件", content: "文件→保存，命名为题目要求（如 1.pkt），保存到\"考生文件夹\\网络\\试题一\"。" }
  ]
}
```

**常见错误**

- ❌ 在 `title` 里手写「1.」「2.」→ ✅ 序号由系统按顺序自动编号，手写会变成「1. 1. 放置设备」。
- ❌ 某步漏写 `title` → ✅ 检查报「步骤[N] title 为空」。
- ❌ 某步写了 `content: ""`（想省略却留了空）→ ✅ 直接删掉 `content` 字段，检查会报「content 为空（如需省略请删掉该字段）」。
- ❌ `items` 为空 → ✅ 检查报「步骤区块缺少 items」。

#### 2.18 一页速记 `summary`

**用途**：放在页面最后的考前回看卡，三段内容按需出现：速记要点 / 必背公式 / 必记结论。

**字段表**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |

| `title` | 选填 | 文字 | 无 | 区块标题，默认显示「一页速记」 |
| `points` | 选填 | 文字清单 | 三项至少填一项 | 速记要点（核心结论清单） |
| `formulas` | 选填 | 文字清单 | 三项至少填一项 | 必背公式（会居中展示） |
| `mustKnow` | 选填 | 文字清单 | 三项至少填一项 | 必记结论（最容易忘、必须记死的点） |

**完整示例（三段都有）**（摘自 `src/content/math/01-集合与逻辑/01-集合的概念与表示.js`）

```js
{
  type: "summary",
  title: "一页速记",
  points: [

    "元素与集合的关系只有两种：\\(a \\in A\\) 或 \\(a \\notin A\\)"
  ],
  formulas: [
    "\\mathbb{N}^* \\subsetneq \\mathbb{N} \\subsetneq \\mathbb{Z} \\subsetneq \\mathbb{Q} \\subsetneq \\mathbb{R}"
  ],
  mustKnow: [
    "含参数的集合必须检验互异性"
  ]
}
```

**最简示例（只写必记结论）**（摘自 `src/content/computer/03-计算机网络技术/02-网络拓扑搭建.js`）

```js
{
  type: "summary",
  title: "一页速记",
  points: [
    "星型拓扑是局域网最常用结构，中心设备故障则全网瘫痪",
    "直通线连不同类型设备；交叉线连同类型设备"
  ],
  mustKnow: ["工程文件按题目要求命名（如 1.pkt）并保存到指定文件夹，这是评分点之一"]
}
```

**常见错误**

- ❌ `points`、`formulas`、`mustKnow` 三个都不写或都为空 → ✅ 至少填一项，否则会显示成一张只有标题的空卡，检查报「points / formulas / mustKnow 至少一项非空」。
- ❌ 某个清单里混入空字符串 → ✅ 检查报「速记区块 存在空元素」，删掉空条即可。
- ❌ 把 `points` 写成一段长文字而不是清单 → ✅ 必须是清单（每条一句）。

#### 2.19 对比 `compare`

**用途**：把两个容易混淆的概念按维度并排对照。**两边地位对等、不分对错**（要表达「错→对」请用 `errorfocus`）。

**字段表（区块本身）**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"compare"` | 声明这是对比块 |
| `title` | 选填 | 文字 | 无 | 区块标题 |
| `left` | **必填** | 文字 | 不能为空 | 左侧名称（如「全称命题」） |
| `right` | **必填** | 文字 | 不能为空 | 右侧名称（如「特称命题」） |
| `aspects` | **必填** | 维度清单 | 至少 1 条 | 每个维度是一行对照 |

**每个维度（aspects 里的一项）的字段**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `label` | **必填** | 文字 | 不能为空 | 对照维度名（如「适用场景」） |
| `left` | **必填** | 文字 | 不能为空 | 左侧在这种维度下的说法 |
| `right` | **必填** | 文字 | 不能为空 | 右侧在这种维度下的说法 |

**完整示例**（摘自 `src/content/math/01-集合与逻辑/06-量词与命题否定.js`）

```js
{
  type: "compare",
  title: "全称命题与特称命题的对比",
  left: "全称命题",
  right: "特称命题",
  aspects: [
    { label: "量词", left: "\\(\\forall\\)（任意）", right: "\\(\\exists\\)（存在）" },
    { label: "形式", left: "\\(\\forall x \\in M, p(x)\\)", right: "\\(\\exists x \\in M, p(x)\\)" },
    { label: "为真的条件", left: "\\(M\\) 中所有元素都满足 \\(p(x)\\)", right: "\\(M\\) 中至少一个元素满足 \\(p(x)\\)" }
  ]
}
```

**常见错误**

- ❌ 少写 `left` 或 `right` → ✅ 检查报「对比区块 left 为空」/「right 为空」。
- ❌ `aspects` 为空或不写 → ✅ 至少要有一个对照维度，否则整块只剩两个名字。
- ❌ 某个维度漏写 `label`、`left` 或 `right` → ✅ 三项都要写，检查会点名「对比维度[N] 某字段为空」。
- ❌ 用本区块表达「这个错、那个对」→ ✅ 那是 `errorfocus` 的语义，两者不可互相顶替。

#### 2.20 术语卡 `vocab`

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `term` | **必填** | 文字 | 不能为空 | 术语本身 |
| `meaning` | **必填** | 文字 | 不能为空 | 术语的准确解释 |

- ❌ `items` 为空 → ✅ 检查报「术语卡区块缺少 items」。

#### 2.21 代码 `code`

#### 2.22 挖空默写 `cloze`

**用途**：把句子里的关键处用 `{{答案}}` 标出来，默认显示成一条虚线空位，点一下揭晓答案。适合古诗文默写、公式填写、命令补全。

**字段表（区块本身）**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `type` | 必填 | 文字 | 固定写 `"cloze"` | 声明这是挖空块 |
| `title` | 选填 | 文字 | 无 | 区块标题 |
| `items` | **必填** | 挖空清单 | 至少 1 句 | 每句是一条挖空文字 |

**每一条（items 里的一项）的字段**

| 字段名 | 是否必填 | 类型 | 约束 | 白话说明 |
| --- | --- | --- | --- | --- |
| `text` | **必填** | 文字 | 不能为空，**必须含成对的 `{{ }}` 且至少一处** | 用 `{{答案}}` 标出空位 |

**完整示例**（摘自 `src/content/chinese/05-文学常识/01-中国文学史.js`）

```js
{
  type: "cloze",
  title: "填空自测（点击空位揭晓）",
  items: [
    { text: "《诗经》\"六义\"：内容分类为{{风、雅、颂}}，表现手法为{{赋、比、兴}}。" },
    { text: "被称为\"诗仙\"\"诗圣\"\"诗佛\"的唐代诗人分别是{{李白}}、{{杜甫}}、{{王维}}。" },
    { text: "王勃名句：海内存知己，{{天涯若比邻}}。" }
  ]
}
```

**常见错误**

- ❌ 用下划线 `______` 表示空位 → ✅ 空位必须写成 `{{答案}}`，数量与位置都由标记决定。
- ❌ `{{` 与 `}}` 数量不配对（如 `{{答案}` 少了一个右括号）→ ✅ 检查报「{{ }} 标记不配对」。
- ❌ 一句里一个 `{{ }}` 都没有 → ✅ 检查报「没有 {{答案}} 标记」。
- ❌ 写了空挖空 `{{}}` 或 `{{   }}` → ✅ 检查报「存在空挖空 {{}}」，空位里必须有答案。
- ❌ `text` 为空，或 `items` 为空 → ✅ 检查报「挖空[N] text 为空」/「挖空区块缺少 items」。

### 附录 A：全校验规则清单

下面按区块归类，左侧是会被检查拒绝的写法，右侧是正确写法。检查命令：`npm run validate:content`。

| 三段都不写或都为空 | 至少填一段 |
| 某个清单里混入空字符串 | 删掉空条 |

#### 对比 `compare`

| ❌ 错误写法 | ✅ 正确写法 |
| --- | --- |
| 不写 `left` / `right` | 两侧名称都要写 |
| `aspects` 为空或不写 | 至少 1 个对照维度 |
| 某个维度漏写 `label` / `left` / `right` | 三项都要写 |

#### 术语卡 `vocab`

| ❌ 错误写法 | ✅ 正确写法 |
| --- | --- |
| 某条漏写 `term` 或 `meaning` | 两个都要写 |

#### 代码 `code`

| ❌ 错误写法 | ✅ 正确写法 |
| --- | --- |
| `code` 为空 | `code` 必填 |
| `code` 里又写了 ``` 围栏 | 只写代码原文 |
| 写了空的 `lang: ""` | 不用就删掉 `lang` 字段 |

#### 挖空 `cloze`

| ❌ 错误写法 | ✅ 正确写法 |
| --- | --- |
| `items` 为空 | 至少 1 句 |
| `text` 为空 | 每句都要有内容 |
| `{{` 与 `}}` 数量不配对 | 成对书写 |
| 一句里没有 `{{ }}` | 至少 1 处空位 |
| 空挖空 `{{}}` | 空位里必须有答案 |

### 附：编写时最容易踩的三个坑

1. **`correctIndex` 从 0 开始**。第一个选项是 `0`，不是 `1`。这是最高频的错误。
2. **公式行结尾别留孤立反斜杠**。行尾一旦是 `\`，公式会变成红字源码。
3. **选填字段要么写全、要么删掉**。想省略 `pinyin`、`content`、`lang`、`tip` 这类字段时，请把整个字段删掉，不要留 `""`。

- **提出方**：教育内容侧（教育专家团：评估专家 / 课程设计师 / 教学法专家）
- **接收方**：功能与布局改进团队
- **日期**：2026-10-09
- **依据**：① `docs/content-authoring-guide.md`（内容侧能力边界与 22 种区块规范）② 三位教育专家的并行评估 ③ 2027 届计算机类考生实战备考需求

## 0. 一句话背景

当前产品的内容体系成熟（141 页 / 22 种区块 / schema 校验），但存在一条清晰的断点：

> **内容侧写得出知识，功能侧接不住训练。**

最典型的三处：
1. 题库 1393 题，**只有 286 题（20.5%）能机器判分**；数学 734 题里只有 60 题能判分
2. **没有错题归因**，错题只能"重做"，不能"开处方"
3. **SM-2 有算法、无执行页**；**没有学习计划模块**

对考生而言，职业技能理论考试是 **60 分钟 / 150 题 / 全客观题**——这是**流畅度测评**，不是知识测评。现有的"题量少、判分弱、无计时、无归因"组合，撑不起这个场景。

## 2. P0 需求详述

### P0-1　判断题自动客观化

- **现状**：内容侧存在大量判断题，其 `answer` 字段**以固定句式开头** —— 正确为「**正确。**…」、错误为「**错误。**…」（见 `content-authoring-guide.md` 2.9 节判断题示例，解析首句即 `**错误。**`）。这些题目前没有 `options` 和 `correctIndex`，因此**不可机器判分**。
- **问题**：判分率被拉低（全库仅 20.5%），大量判断题只能靠自评，而自评结果会直接进组卷权重，可能把练习导向**假薄弱单元**。
- **期望**：构建或运行时**解析 `answer` 首句**，自动派生出 T/F 两个选项与 `correctIndex`，使之进入可判分集合。**不需要内容侧改任何一个字。**
- **验收标准**：
  1. 对 `answer` 以「正确。」/「错误。」开头的题，自动生成二选一选项并可点选判分
  2. 派生题与人工题**分开统计**（标记 `derived: true`），结果页能区分
  3. 首句匹配失败的题**保持原样不判分**，不误判
  4. `npm run validate:content` **不因本改动新增报错**
- **内容侧配合**：我们会保证新增判断题沿用「**正确。**/**错误。**」开头这一约定。

### P0-2　填空题答案规整与判分

- **现状**：填空题（`type: "fill"`）只有 `answer` 文本，无结构化答案，**全部不可判分**（数学 734 题仅 60 题可判分，主因在此）。
- **问题**：数学是用户优势科目，却几乎没有可判分的填空训练；语文同理。
- **期望**：引入**答案规整器**（normalizer）后再比对，而非精确字符串匹配。
- **验收标准**：以下等价判定应成立（可逐步实现，按学科分批）：
  1. 数值容差：`0.5` == `1/2` == `0.500`
  2. 分数 ↔ 小数互认
  3. **集合 / 区间归一**：`{x|-1≤x≤3}` == `[-1,3]`，`x>5或x<-1` == `(-∞,-1)∪(5,+∞)`
  4. 剥离 LaTeX 包裹（`\(...\)`、`$$...$$`）后比对
  5. 全角/半角、多余空格容错
  6. 匹配失败时**回落为自评**，不判错、不阻塞
- **内容侧配合**：可在必要时为填空增加结构化答案字段（如 `answerNorm`），但**优先靠规整器解决**，不改存量内容。

### P0-3　单题耗时 `elapsedMs` 采集

- **现状**：`exam` 块只有整卷 `duration`；无逐题耗时。练习会话也无单题计时。
- **问题**：理论考 150 题 / 60 分钟 ≈ **24 秒/题**，属流畅度测评。**没有单题耗时就测不出卡顿点**，训练只能凭感觉。
- **期望**：练习与考试均记录每题耗时。
- **验收标准**：
  1. 数据结构含每题 `elapsedMs`，并随同步上传
  2. 结算页能展示**耗时最长的题目 Top N**
  3. 单题超过阈值（建议 45 秒，可调）时**标记提示**，并可一键归因「超时」
  4. 数据可用于组卷（可复现的卡顿单元优先）

### P0-4　错题归因字段

- **现状**：`error_book` 无归因字段（全库无 `reason` / 归因相关字段）。错题只能重做。
- **问题**：**只能重做，不能开处方。** 学生不知道自己是"概念不清"还是"计算失误"，复习没有针对性。
- **期望**：为错题增加最小归因字段。
- **验收标准**：
  1. 数据结构：`reason`（六选一：**概念不清 / 记错公式 / 计算失误 / 审题偏差 / 步骤缺失 / 超时蒙猜**）+ `kp`（知识点标签，先自由文本，后续沉淀字典）+ `wrongCount`
  2. 交互：自评后弹出**二级归因层**，≤6 个 chip，**一点即完成**，允许跳过（不做强制，避免打断）
  3. 错题本可按 `reason` 筛选，并可查看**归因分布**
  4. 归因结果与自动判分结果**分别统计，不合并**
- **内容侧配合**：后续可在题目上补 `kp` 标签，但**不阻塞本需求**——先支持自由输入即可。

### P0-5　限时仿真模式（分段速度训练）

- **现状**：练习组卷只控制题量（10–50），`exam` 块有 `duration` 但面向整卷。
- **问题**：理论考是 150 题 / 60 分钟，现有训练**没有对应密度的档位**。
- **期望**：新增限时模式，并支持分段进阶。
- **验收标准**：
  1. 三档预设：**25 题 / 10 分钟** → **50 题 / 20 分钟** → **150 题 / 60 分钟**（仿真档需允许包含真题卷）
  2. 倒计时结束自动交卷；中途可提前交卷
  3. 结算展示**正确率 + 平均单题耗时 + 超时题数**
  4. 仿真档间隔建议 ≥14 天（题库量有限，避免重复）—— 可做成温和提示，非强制

### P0-6　复习器单页（到期队列 + 四档评分）

- **现状**：`useSpacedReview.js` 有 `calculateSM2()` / `loadDueReviews()` / `loadReviewStats()`，但**未接入独立复习页**；且 Dashboard 自算的 `todayDue`（`!e.reviewed && nextReviewDate <= 今天`）与 composable 的 `dueReviews`（含"从未复习"分支）**口径不一致**。
- **问题**：SM-2 当前是**伪参数**——错题本「已掌握」固定传 `grade=4`，quality 恒定，间隔计算不可信。
- **期望**：落地一个**单卡会话式**复习页（交互形态由你们定，可参考 `PracticeSession.vue` 的一屏一题骨架）。
- **验收标准**：
  1. 有独立入口，建议**前置到首页顶部**，且**先复习、后学新**
  2. 单次上限 20–30 张，队列可清零（**清得完才有完成感**）
  3. 流程：先自答 → 翻面 → **四档评分**（忘了 / 困难 / 良好 / 简单）→ 下一题
  4. **四档评分必须真实传入 `calculateSM2`**，不得再固定传 4
  5. **合并两处 due 口径**（Dashboard 与复习页数字必须一致）
  6. 空队列显示"今日已清零"并引导新内容，**不显示空态**

### P0-7　学习计划三件套

- **现状**：全库无 `studyPlan` / 排课 / 日程模块。
- **问题**：用户是 2027 届考生，**技能操作考 2026-11-30（距今 52 天）**，周预算 32 小时。没有计划载体就看不出**切换点**——操作考是"合格即满分"，过线后边际收益下降，时间应转投语文数学。**没有表就很容易全程均分、后期挤压。**
- **期望**：最小可行的计划功能，**不做排课算法**。
- **验收标准**：
  1. **周预算表**：科目 × 小时，手填，**校验合计 = 32h**（不符给提示，不阻断）
  2. **里程碑倒计时**：11/30（操作考）、次年 4 月（理论考）、6/7（语数）——前后两段配比可不同
  3. **每日清单**：今日复习 + 本周该科任务 + 实际耗时对比预算
  4. **漏一天自动顺延，不惩罚、不清零**（避免羞辱式设计）

### P0-8　`cloze` 挖空块支持"输入默写"

- **现状**：`cloze` 块目前是**点击空位揭晓答案**（见 authoring guide 2.22 节），学生无法先默写再核对。
- **问题**：**古诗文默写是语文提分性价比最高的板块**（纯记忆、有标准答案），但现有实现只能"看"，不能"默"。
- **期望**：`cloze` 增加**输入模式**——先输入，再比对揭晓。
- **验收标准**：
  1. 空位可输入文本（移动端输入体验需专门处理）
  2. 提交后**逐空比对**，标出对错；判分采用与 P0-2 相同的规整逻辑（至少支持：去空格、全半角、常见异体字/通假容错）
  3. 支持"**全部重默**"与"**只看错的那句**"
  4. 默写结果能进错题/复习队列（与 SM-2 打通）
  5. **向后兼容**：不写输入模式的存量 `cloze` 维持"点击揭晓"行为

## 6. 硬约束提醒（请在实现时遵守）

1. **页面顺序即身份**：`site.js` 的 `files` 数组顺序决定 `fileIndex`，进而决定路由与进度归属。**禁止插入或重排**，新增一律追加末尾。
2. **内容 schema 校验**：任何涉及内容结构的改动，必须保证 `npm run validate:content` 仍全绿；新增字段请先与内容侧确认是否进 `schema/content-schema.json` 白名单。
3. **CSP 极严**：`script-src 'self'`，禁止 `unsafe-*` / 运行时 `eval` / 动态注入脚本。判分与规整逻辑请用静态代码实现。
4. **判分与自评强制二分**：现有"自动判分"与"自评"结果**分开统计、禁止合并**（这是干净的专业做法，请勿合并）。
5. **移动端为主、桌面端为辅**：用户是 Tauri 桌面 + 移动端双端；但周末 8 小时是**电脑端实操**（PS/PR），桌面端体验同样重要。
6. **不承诺结果**：任何界面文案**不得出现**提分/保过/录取承诺与极限词；倒计时与进度只作过程呈现。

## 7. 建议排期（供参考，最终由你们定）

- **第一梯队（相互独立，可并行）**：P0-1、P0-3、P0-4 —— 都是数据/解析层，改动小、收益大
- **第二梯队**：P0-2（填空规整，可分学科分批）、P0-5、P0-8
- **第三梯队**：P0-6、P0-7（页面级，工作量较大，建议优先 P0-6，因为 SM-2 目前完全不生效）
- **依赖提醒**：P0-8 与内容侧「默写专项」强耦合，建议**排在同一迭代**；P1-10（卡点本）依赖 P0-6 的复习队列先落地。

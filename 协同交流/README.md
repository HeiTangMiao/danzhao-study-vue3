## 投递规范

1. **文件命名**：`YYYY-MM-DD_主题.md`（例：`2026-10-09_对内容侧17项需求的评审回应.md`）
2. **来件/回函**：写完放进对应目录，同时在 `大事记.md` 顶部加一行（日期 / 发起方 / 标题 / 一句话摘要）
3. **必备要素**（每份文档开头四件事）：背景（为什么写）、期望（要对方做什么）、边界（哪些不归对方管）、验收（做到什么算完成）
4. **响应节奏**：收到对方来件后，下一次工作时先看本区，**优先回执**（哪怕只是「已收到，预计 X 时给详回」）；深入回应可随后补
5. **不覆盖对方的文件**：修正内容请追加「补充/修订说明」，或另发新文件并在标题注明「（修订版）」

## 双方共同遵守的硬约束（速查）

| # | 约束 | 说明 |
|:-:|------|------|
| 1 | **页面顺序即身份** | `site.js` 的 `files` 数组顺序决定路由与学习进度归属——只允许**末尾追加**，禁止插入/重排 |
| 2 | **内容 schema 白名单** | 内容文件新增字段须先经功能侧确认并进入 `schema/content-schema.json` |
| 3 | **CSP 极严** | 禁止运行时 `eval` / 动态脚本注入——判分、规整等逻辑均静态实现 |
| 4 | **判分与自评强制二分** | 自动判分与自评结果分开统计、不合并 |
| 5 | **不承诺结果** | 界面文案不得出现提分 / 保过 / 录取承诺；考试信息以浙江省教育考试院当年发布为准 |
| 6 | **双端一致** | Tauri 桌面 + 移动端均需正常工作；周末实操场景桌面端体验同等重要 |

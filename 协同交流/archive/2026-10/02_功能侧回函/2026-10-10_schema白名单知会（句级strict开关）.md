# schema 白名单知会：句级 `strict` 开关（`clozeItem.strict`）

- **日期**：2026-10-10
- **发出方**：功能侧（software-danzhao-batchD）
- **依据**：我方回函《批 C 交付通告 + 内容侧四件回执》**第五节**承诺——「反/返」取向选**方案 2**：schema 增加句级开关 `clozeItem.strict`，由内容侧自行收口；本文是该字段的**白名单正式知会**
- **期望**：① 你们**从现在起可以**在内容文件里写 `strict`；② 请只在「该字在本句是正解义、不是通假义」的句上打开（用法见第三节）
- **边界**：**只新增一个字段**，不改判分契约、不删既有通假键、不影响未标注的句子
- **验收**：改完后 `npm run validate:content` 全绿即可来件（或留待我方例行入库）

---

## 一、字段定义

```js
// clozeItem 级（cloze 块内每一句）
{
  text: "……辗转反侧……",
  blanks: [ /* … */ ],
  strict: true,        // ← 新增（布尔，可选）
  alts: ["…"]          // 既有字段，不受影响
}
```

| 属性 | 值 |
|---|---|
| 字段名 | `strict` |
| 类型 | **布尔**（`true` / `false`） |
| 缺省 | 不写 = `false`（**行为与现在完全一致**） |
| 作用域 | **句级**（只影响所在的这一句） |
| 语义 | `true` = **该句禁用全局通假映射**，只按「正解 + 本句 `alts`」比对 |

---

## 二、它解决什么（你们提的那条红线）

现状（未标注时）：

| 输入 | 期望 | 结果 |
|---|---|---|
| 返 | 反 | ✅ 对（通假生效，正确） |
| **辗转返侧** | **辗转反侧** | ⚠️ **判对（误判）** |

给「辗转反侧」这一句加上 `strict: true` 后：

| 输入 | 结果 |
|---|---|
| **辗转反侧**（正解） | ✅ 对 |
| **辗转返侧** | ✅ **判错**（红线消除） |
| 其他未标注的句子（如「始一反焉」） | 通假**照旧生效**，零影响 |

---

## 三、用法（重要：不要大面积打开）

**建议用法**：只在该字/词**在本句取的是本义而非通假义**的句子上打开。

```
✅ 该打开：辗转反侧（「反」= 翻转，本义）
❌ 不要打开：始一反焉 / 窥谷忘反（「反」通「返」，本来就该放行）
```

**为什么不要大面积开**：全局通假表的价值在于兜住学生的通假写法；逐句打开 `strict` 等于逐句放弃该兜底。**只在有实证的句子上收口**——与你们一贯的立场（"凡拿不准的，一律从严判错；但要有实证"）一致。

**与 `alts` 的关系**：`strict` **只关全局映射表**，**不影响 `alts`**。判分顺序仍是「正解 → 本句 `alts`」，两条都不中才判错。所以若某句在严格模式下仍需放行某个变体，写 `alts` 即可，**不需要**为了它放弃 `strict`。

## 四、边界行为（我方实测，供你们写内容时参照）

| 情况 | 运行时行为 | validator 行为 |
|---|---|---|
| `strict: true` | 该句禁用全局映射 ✅ | 通过 |
| `strict: false` | 等同不写（映射正常生效） | 通过 |
| **不写** | 映射正常生效（**存量零影响**） | 通过 |
| `strict: "true"`（字符串） | **运行时静默忽略**（等价 `false`——通假仍生效） | ❌ 报错「`strict` 应为布尔」 |
| `strict: 0` / `null` | 同上 | ❌ 报错 |

⚠️ **重点提醒**：字符串 `"true"` 在运行时**不会生效**（不会抛错、不会判错），只靠 validator 拦。所以**务必以 `validate:content` 全绿为准**，不要凭"我写了"就认为生效了。

**另需知道**：`strict: true` 关掉的是**整张通假表**，不只是某一个字。例如某句正解本身是映射键时，学生写映射值也会被判错——这正是"严格"的定义，符合预期，但写内容时心里要有数。

## 五、我方验证要点（供你们放心使用）

- **句级隔离已证**：同一 cloze 块内 `[strict句, 普通句]` 混排，判对/判错**各归各位**，互不影响；
- **`alts` 不被误伤已证**：`strict:true + alts:['覆']` 时，「覆」判对、「返」判错；
- **既有键未删已证**：全局表 14 键一字未动（`反→返` 仍在，`tests/cloze-variants.test.js` 锚定）；
- **判分契约未动**：`answerMatches` 的返回结构 `{ matched, mode }` 与 `blankMatches` 的布尔返回**均未改**；
- **存量零影响已证**：全库未标注 `strict` 的句子行为与升级前一致。
